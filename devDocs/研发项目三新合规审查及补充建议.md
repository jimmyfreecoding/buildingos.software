## 一、审查依据

1. 《财政部 国家税务总局 科技部关于完善研究开发费用税前加计扣除政策的通知》（**财税〔2015〕119号**）——研发活动定义及负面清单
2. 《四川省企业研究开发费用加计扣除项目鉴定实施细则》第七条——鉴定所需资料
3. 国家税务总局《研发费用加计扣除政策执行指引（2.0版）》——研发活动判断要点
4. 科技部、税务总局联合发布的研发项目鉴定典型案例——判断逻辑参照

### 研发活动的法定定义

> 研发活动是指企业为获得**科学与技术新知识**，**创造性运用**科学技术新知识，或**实质性改进**技术、产品（服务）、工艺而持续进行的具有明确目标的系统性活动。

### 不适用加计扣除的情形（负面清单节选）

- 对现存产品、服务、技术、材料或工艺流程进行的**重复或简单改变**
- 商品化后期的费用活动
- **运用已知方法对现存产品进行简单改变**或在研发中**运用现有软件工具进行商业应用软件和信息系统的开发**

### 鉴定专家判断的四要素

| 要素 | 说明 |
|------|------|
| 1. 明确创新目标 | 是否旨在获得新知识或实质性改进 |
| 2. 系统组织形式 | 是否有立项决议、研发团队、研发计划 |
| 3. 结果不确定性 | 是否存在技术风险，需要反复试验验证 |
| 4. 佐证资料充分 | 实验记录、测试报告、技术文档等 |

## 六、论证通用法则（答辩指导）

### 核心逻辑链

> **现有技术能解决什么 → 现有技术解决不了什么 → 我们攻破了哪个"解决不了"的点 → 攻破过程中遇到了什么不确定性 → 怎么验证的**

**关键提示**：专家最怕听到的是"我们开发了一个系统实现了XX功能"——这是产品描述。要让专家听到的是"XX技术问题目前没有成熟方案，我们通过研究试验，找到了一种解决方法，过程中经历了XX失败和调整"。

### 逐项目答辩口径

| 项目 | 专家可能质疑 | 应对口径 |
|------|-------------|----------|
| **AIoT预研** | "这不就是代码重构/技术整合吗" | 7种协议通信模型本质不同，简单封装做不到统一接入。我们研究设计了协议无关的统一指令模型，这个抽象过程没有现成答案，需反复试验确定抽象粒度 |
| **空间预约** | "预约排程是成熟领域" | 通用排程只做时间冲突检测。楼宇空间预约要同时满足时间+容量+规则+设备配套多维约束，还需要传感器联动实时感知占用状态，现有通用预约系统不具备这些能力 |
| **访客系统** | "这就是OA访客管理" | 我们的核心不是流程线上化，是临时通行权限的安全闭环管控。临时权限的跨系统原子性下发和离线场景回收是分布式一致性问题，和OA审批流程本质不同 |
| **卫生间系统** | "这就是阈值告警+规则引擎" | 单阈值告警误报率极高，无法区分"需清洁""设备故障""传感器漂移"。我们设计了多维度数据融合研判规则，通过时序关联和多条件组合判断告警根因，规则设计本身是技术攻关 |
