# 3.3 门禁管理

## 需求概述

本系统提供覆盖全园区的一体化门禁管理解决方案，支持工卡、人脸、二维码等多种通行方式，实现"门禁点 → 门禁组 → 门禁角色"三级权限管理架构，与飞书系统深度联动实现入职自动授权、离职自动回收。同时提供标准化开放 API，与企业考勤、HR 等第三方系统无缝集成，并原生打通访客、工单、停车等园区业务模块。

---

## 3.3.1 整体架构

### 三级权限管理模型

系统采用"门禁点 → 门禁组 → 门禁角色"的三层抽象，屏蔽底层硬件设备的复杂性：

```
物理设备层
  ├── 门禁控制器 A（北门入口）
  ├── 门禁控制器 B（2F 办公区东）
  ├── 门禁控制器 C（3F 办公区）
  └── ...
        │
        ▼
门禁点层 (Door Point)              ← 逻辑抽象，绑定物理设备
  ├── 北门入口 (type: 大楼通行)
  ├── 2F 办公区东 (type: 层内通行)
  ├── 3F 办公区 (type: 楼层通行)
  └── ...
        │
        ▼
门禁组层 (Door Group)              ← 按空间/功能聚合门禁点
  ├── A栋通行组 (北门入口 + 1F 电梯 + 2F 办公区 + 3F 办公区)
  ├── B栋通行组
  └── 访客通行组 (北门入口 + 1F 电梯)
        │
        ▼
门禁角色层 (Access Role)           ← 组合门禁组 + 有效期
  ├── 正式员工角色 (A栋通行组 + B栋通行组, 长期有效)
  ├── 实习生角色 (A栋通行组, 6个月)
  └── 访客角色 (访客通行组, 1天)
        │
        ▼
用户 (User)                        ← 关联一个或多个角色
  └── 张三 → 正式员工角色 → 获得A栋+B栋全部门禁点的通行权限
```

**核心优势**：当新增或变更门禁点时，只需将其加入对应的门禁组，所有关联该组的角色自动获得新点位的通行权限，无需逐个用户调整。

### 通行方式支持

| 方式 | 适用场景 | 技术实现 |
|------|---------|----------|
| 工卡 (RFID/IC) | 正式员工、外包人员日常通行 | 读卡器读取卡号，匹配后台权限 |
| 人脸识别 | 正式员工无感通行、高安全区域 | 旷视( Megvii ) / 海康( Hikvision ) 人脸识别终端，底库照片云端同步 |
| 二维码 | 访客、临时人员短期通行 | 动态生成临时二维码，有效期绑定，过期失效 |
| 远程开门 | 管理员应急处置、访客远程放行 | 管理员在后台一键下发开门指令 |

## 3.3.2 人员管理

### 人员信息管理

系统通过人脸库模块（FaceLib）统一管理所有通行人员的凭证信息。界面采用左树右表的经典布局：

- **左侧**：组织架构树，支持按部门筛选，同时支持自定义分组（如"访客临时组"）
- **右侧**：人员数据表格，支持按姓名搜索，分页展示

**人员信息字段：**

| 字段 | 说明 |
|------|------|
| ID | 系统唯一标识 |
| 人脸照片 | 点击可放大预览，支持 PNG/JPEG 格式，最大 200KB |
| 真实姓名 | 显示性别图标（男/女） |
| 旷视推送状态 | 待推送（红点）/ 已推送成功（绿点）/ 推送失败并显示错误信息 |
| 海康推送状态 | 同上，独立追踪 |
| 卡号 | 支持点击行内编辑 |
| 工号 | 企业内部工号 |
| 虚拟工号 | 系统生成的虚拟编号 |
| 邮箱 | 电子邮箱 |
| 所属部门 | 组织架构路径 |
| 在职状态 | 在职（绿色标签）/ 离职（红色标签）/ 转岗（橙色标签） |

**人员操作：**

| 操作 | 说明 |
|------|------|
| 新增人员 | 仅可在自定义分组下新增临时人员，需填写真实姓名和卡号 |
| 编辑卡号 | 点击表格中卡号字段即可行内编辑 |
| 上传人脸 | 点击人脸字段上传照片，PNG/JPEG 格式，最大 200KB，上传后自动通过 MQTT 推送至下游设备 |
| 删除人员 | 支持单行删除和批量勾选删除（需 Admin 角色 + `delete:system` 权限），二次确认 |
| 人脸下发 | 每行"下发"按钮，通过 MQTT `/iot/action/user/face/push` 将人脸数据推送至旷视/海康终端 |

### 按人员类型分类管理

系统支持按以下人员类型进行分类管理，每种类型的权限策略可独立配置：

| 人员类型 | 标识 | 说明 |
|----------|------|------|
| 正式员工 | employee | 长期有效，入职自动赋权，离职自动回收 |
| 实习生 | intern | 有效期通常绑定实习期，到期自动回收 |
| 外包人员 | outsource | 按项目周期授权，支持按供应商分类 |
| 驻场供应商 | supplier | 按服务合同期限授权 |
| 临时人员 | temp | 短期通行，支持按天/周设置有效期 |
| 访客 | visitor | 被访人邀请或自主预约，限时通行 |
| VIP | vip | 高级通行权限，通常覆盖全园区 |

**自动分类联动**：当人员类型发生变更时（如实习生转正式员工），系统自动根据新类型匹配对应的默认权限规则，重新计算并更新其门禁权限，无需人工干预。

### 按部门分配权限

系统支持按部门维度批量分配门禁权限。管理员选择目标部门后，该部门下所有成员自动继承部门级权限策略。部门权限变更时，系统自动同步更新该部门下所有成员的通行权限。

### 特殊人员权限封阻

对于需要临时限制通行的人员（如离职交接期、安全事件调查期），管理员可对其账号执行"权限封阻"操作：
- 封阻期间该人员的所有通行权限暂时冻结，无法通过任何门禁点
- 门禁通行记录中保留封阻标记
- 解封后权限自动恢复至封阻前状态
- 封阻操作记录在审计日志中

## 3.3.3 批量操作

### 批量导入权限

系统提供拖拽式文件上传区域，支持通过 Excel 文件（.xlsx / .xls）批量导入人员门禁权限信息：

- **导入方式**：支持按 `user_id`、`open_id`、手机号三种方式匹配人员
- **上传交互**：拖拽文件到上传区域或点击选择文件，单文件上传
- **导入结果**：处理完成后弹出结果面板，清晰展示总数、成功数、失败数
- **错误详情**：失败记录附带失败原因（如"用户不存在""门禁点编码错误"等）

### 批量导出权限

支持一键导出全部人员的人脸照片、工卡号等凭证信息，用于线下存档或审计：

- 导出格式：Excel (.xlsx)
- 导出范围：可选择全部人员或按部门/人员类型筛选后导出
- 包含信息：姓名、工号、卡号、人脸照片 URL、所属部门、授权门禁点列表

### 批量回收权限

支持按人员范围批量回收门禁权限：
- 选择目标人员（勾选或按条件筛选）
- 选择要回收的门禁组或门禁角色
- 确认后批量移除权限关联
- 操作结果记录在操作日志中

### 操作日志

所有批量操作（导入、导出、赋权、回收）均记录完整操作日志：

| 日志字段 | 说明 |
|----------|------|
| 操作类型 | 导入赋权 / 导出凭证 / 批量回收 / 批量授权 |
| 文件名 | 导入/导出的文件名 |
| 处理数量 | 总数 / 成功数 / 失败数 |
| 操作人 | 执行操作的管理员姓名 |
| 操作时间 | 精确到秒的操作时间戳 |
| 执行状态 | 成功（绿色）/ 部分成功（橙色）/ 失败（红色） |

## 3.3.4 门禁角色

### 角色统一管理

门禁角色是由一个或多个门禁权限组组合而成的权限集合。系统支持按用户、供应商、服务商、临时人员、访客、VIP 等多种角色类型进行统一管理。

**角色列表：**

| 展示字段 | 说明 |
|----------|------|
| 角色名称 | 如"正式员工角色""访客角色""外包人员角色" |
| 包含权限组 | 以彩色标签展示该角色关联的所有门禁组 |
| 关联用户数 | 当前拥有此角色的用户总数 |
| 有效期 | 角色生效时间范围（起止日期） |
| 描述 | 角色的说明信息 |

**角色操作：**

- **新增角色**：填写角色名称、选择包含的权限组（多选）、设置有效期、填写描述
- **编辑角色**：修改角色关联的权限组或有效期
- **删除角色**：删除前检查是否有关联用户，有则提示先解除关联

### 角色叠加与有效期

- **多角色叠加**：一个用户可以添加多个门禁角色，最终通行权限取所有角色关联门禁组的并集
- **时间调度**：每个门禁组可配置时间模板（全部时间 / 工作日 / 周末 / 节假日），精细化控制不同时段的通行规则
- **有效期控制**：每个角色可设置独立的有效期，到期后自动失效，通行权限自动回收，无需管理员手动操作
- **到期提醒**：角色即将到期时，系统自动向管理员和用户发送到期提醒

### 时间模板配置

门禁权限支持四种时间模板，按需灵活组合：

| 时间模板 | 适用场景 |
|----------|---------|
| 全部时间 | 7×24 全天候通行（如安保人员） |
| 工作日 | 周一至周五通行（如正式员工） |
| 周末 | 周六、周日通行（如周末值班人员） |
| 节假日 | 法定节假日通行（如假期值班人员） |

## 3.3.5 门禁点管理

### 门禁点配置

系统支持将物理门禁设备抽象为逻辑门禁点，统一管理：

| 配置项 | 说明 |
|--------|------|
| 门禁点名称 | 如"北门入口""2F 办公区东""3F 办公区" |
| 门禁点类型 | 大楼通行 / 楼层通行 / 层内通行 |
| 所属空间位置 | 空间编码 → 楼栋 → 楼层 → 区域 |
| 门禁品牌 | 设备品牌（如旷视、海康） |
| 绑定设备 | 可绑定一个或多个物理设备 |

### 门禁点实时状态

系统以可视化沙盘或地图视图展示门禁点的实时运行状态：

| 状态 | 颜色标识 | 说明 |
|------|---------|------|
| 在线 | 绿色 | 设备正常通信 |
| 开门 | 绿色闪烁 | 门磁信号为开门状态 |
| 关门 | 灰色 | 门磁信号为关门状态 |
| 离线 | 红色 | 设备通信中断 |

### 门禁模式与远程控制

| 模式/指令 | 说明 |
|-----------|------|
| 正常模式 | 按权限规则正常通行 |
| 常开模式 | 门禁保持常开（如上下班高峰期、消防疏散） |
| 常闭模式 | 门禁保持常闭（如安全事件封锁） |
| 远程开门 | 管理员一键远程下发开门指令 |
| 远程关门 | 管理员一键远程下发关门指令 |

所有控制指令支持单点操作和批量操作，指令下发后实时反馈执行结果。

## 3.3.6 门禁组管理

### 门禁组配置

门禁组是按空间或功能维度对门禁点的逻辑聚合，是连接门禁点与门禁角色的中间层。

**门禁组列表：**

| 展示字段 | 说明 |
|----------|------|
| 组名称 | 如"A栋通行组""B栋通行组""访客通行组" |
| 包含门禁点 | 以可关闭标签（closable tag）展示，点击标签上的 × 可直接移除该门禁点 |
| 门禁点数量 | 组内门禁点总数 |
| 描述 | 组的说明信息 |

**门禁组操作：**

- **新增组**：填写组名称、选择门禁点（多选）、填写描述
- **编辑组**：增删组内的门禁点
- **删除组**：删除前检查是否被门禁角色引用

### 自动聚合与自定义分组

| 分组方式 | 说明 |
|----------|------|
| 按楼栋自动聚合 | 选择楼栋，自动将该楼栋下所有门禁点组成标准组 |
| 按楼层自动聚合 | 选择楼层，自动将该楼层下所有门禁点组成标准组 |
| 自定义分组 | 手动选择任意门禁点组合，不受空间限制 |

### 通行组（PassGroup）— 旷视分组管理

针对旷视（Megvii）人脸识别平台的组管理，系统提供独立的通行组管理模块：

- 展示所有旷视识别终端的分组列表
- 支持按组筛选成员
- 支持向组内添加/移除人员
- 支持按组导出人员数据
- 远程搜索人员（按姓名模糊匹配，显示姓名+工号+部门）

## 3.3.7 默认权限规则

### 自动赋权引擎

系统提供基于规则的自动赋权引擎，根据人员的多维属性自动匹配并赋予对应的门禁角色和梯控角色，实现人员入职自动授权、类型变更自动调整、离职自动回收。

**规则匹配维度：**

| 维度 | 说明 | 示例 |
|------|------|------|
| 公司/组织 | 所属企业或组织 | 智谱集团 / 子公司A |
| 部门 | 所属部门 | 技术部 / 产品部 / 运营部 / 行政部 / 财务部 |
| 人员类型 | 全职员工 / 实习生 / 外包人员 / 驻场供应商 | employee / intern / outsource / supplier |
| 工作园区 | 人员归属的办公园区/空间 | ZP 园区 / 分园区A |

**规则配置项：**

| 配置项 | 说明 |
|--------|------|
| 规则名称 | 如"全职员工默认规则""实习生默认规则" |
| 适用类型 | 从人员类型、部门等多维下拉中选择 |
| 适用部门 | 可选择多个部门（全选或部分） |
| 授权门禁组 | 选择命中规则后自动赋予的门禁组（多选） |
| 授权梯控角色 | 选择命中规则后自动赋予的梯控权限 |
| 优先级 | 数字 1-9999，数值越小优先级越高，用于解决规则冲突 |
| 启用/禁用 | 开关控制规则是否生效 |

**规则触发时机：**

| 触发场景 | 行为 |
|----------|------|
| 人员入职 | 根据人员类型和部门匹配规则，自动赋予初始门禁权限 |
| 人员类型变更 | 实习生转正式 → 自动移除实习生规则权限，应用正式员工规则权限 |
| 部门调动 | 从技术部调至产品部 → 自动调整门禁权限至新部门规则 |
| 规则变更 | 管理员修改规则配置 → 关联的所有人员权限自动刷新 |
| 人员离职 | 自动回收所有门禁权限（可通过 AutoAuth 联动飞书实现） |

## 3.3.8 门禁自动赋权（飞书联动）

### 飞书深度集成

系统与飞书系统深度联动，实现入离职人员门禁权限的全自动化管理：

**配置项：**

| 配置项 | 说明 |
|--------|------|
| 启用自动赋权 | 总开关，关闭后所有自动操作暂停 |
| 飞书 App ID | 飞书企业自建应用的 App ID |
| 飞书 App Secret | 飞书应用的密钥（密码框加密显示） |
| 审批定义 Code | 飞书审批流定义编码，匹配对应的审批流程 |
| 入职自动授权 | 开启后，飞书审批通过（入职审批）→ 自动赋予门禁角色 |
| 离职自动回收 | 开启后，飞书审批通过（离职审批）或检测到离职状态 → 自动回收全部门禁权限 |
| 同步间隔 | 定时同步周期（1-1440 分钟可配置） |

**自动赋权流程：**

```
飞书 OA 系统
    │
    ├── 入职审批通过 → Webhook 回调 → 平台接收
    │     │
    │     ├── 创建/激活用户账号
    │     ├── 匹配默认权限规则（按人员类型 + 部门）
    │     ├── 自动赋予门禁角色 + 梯控角色
    │     ├── 下发人脸/卡号至门禁终端
    │     └── 记录自动赋权日志
    │
    ├── 离职流程触发 → Webhook 回调 → 平台接收
    │     │
    │     ├── 立即回收全部门禁权限
    │     ├── 从门禁终端删除该用户凭证
    │     ├── 标记用户状态为"离职"
    │     └── 记录自动回收日志
    │
    └── 人员变更 → Webhook 回调 → 平台接收
          │
          ├── 识别新的身份信息（部门/岗位/类型）
          ├── 移除旧权限（基于旧身份）
          ├── 重新匹配默认权限规则
          ├── 赋予新权限（基于新身份）
          └── 记录身份变更日志
```

**自动赋权日志：**

| 日志字段 | 说明 |
|----------|------|
| 人员姓名 | 操作对象 |
| 所属部门 | 部门路径 |
| 操作类型 | "自动授权"（绿色标签）/ "自动回收"（橙色标签） |
| 授权的门禁组 | 具体被赋权或回收的门禁组名称 |
| 触发条件 | 如"飞书审批通过""离职流程完成""部门变更" |
| 操作时间 | 精确到秒 |
| 执行状态 | 成功（绿色）/ 失败（红色） |

## 3.3.9 综合权限查询

### 一站式权限检索

系统提供综合权限查询功能，输入人员标识信息即可一览其全部通行权限：

**查询入口**：输入员工姓名、手机号、工号任一信息进行检索

**查询结果展示：**

| 字段 | 说明 |
|------|------|
| 姓名 | 员工姓名 |
| 工号 | 企业工号 |
| 部门 | 所属部门路径 |
| 门禁角色 | 以彩色标签列出该员工拥有的所有门禁角色 |
| 授权门禁组 | 列出所有授权门禁组名称 |
| 授权门禁点 | 前 3 个直接展示，超过 3 个时显示 "+N more" 悬浮气泡（Popover）展示完整列表 |
| 权限有效期 | 最早到期时间标注 |
| 通行状态 | 实时计算：具备通行资格（绿色）/ 已过期（红色）/ 已封阻（灰色） |

### 权限来源追溯

每条权限均明确标识来源，帮助管理员快速理解权限的授予路径：

| 来源类型 | 标识 | 说明 |
|----------|------|------|
| 角色授权 | "角色：XXX" | 通过门禁角色获得的权限 |
| 规则生成 | "规则：XXX" | 通过默认权限规则自动匹配生成的权限 |
| 手动授权 | "手动添加" | 管理员手动单独添加的权限 |
| 直接授权 | "直接授权：门禁点 XXX" | 直接授予门禁点的权限（不经过角色/组） |

### 实时通行资格计算

系统在查询时实时计算当前时刻该员工是否具备通行资格，综合考虑：

1. **时间模板**：当前时间是否在权限的通行时段内（如仅在"工作日"有效的权限，周末查询结果显示"暂不可用"）
2. **角色有效期**：关联的每个角色是否在有效期内
3. **封阻状态**：账号是否被标记为封阻
4. **门禁点状态**：目标门禁点是否在线/正常模式

最终计算结果以颜色区分的状态标签直观展示。

### 权限导出

查询结果支持导出为 CSV 文件（UTF-8 BOM 编码，中文兼容），导出字段包括：姓名、工号、部门、角色、门禁组、门禁点、有效期、当前通行状态。

## 3.3.10 外部人员管理

### 外部人员信息库

系统为外部人员建立独立于正式员工的信息档案，支持以下外部人员类型：

| 类型 | 说明 | 典型场景 |
|------|------|---------|
| 施工人员 | 园区施工、装修人员 | 短期驻场，通常 1-4 周 |
| 长期快递 | 固定快递收发人员 | 长期但有固定访问时段 |
| 活动部署 | 会议/活动临时人员 | 通常 1-3 天 |
| 供应商 | 驻场供应商技术人员 | 按合同周期 |
| 服务商 | 保洁/安保外包人员 | 按服务合同周期 |

**外部人员信息字段：**

| 字段 | 说明 |
|------|------|
| 姓名 | 必填 |
| 手机号 | 必填，作为联系方式 |
| 身份证号 | 用于身份核验 |
| 人员类型 | 访客 / 外包 / 临时人员（颜色标签区分） |
| 所属公司 | 外部人员归属的公司/组织 |
| 接待人/被访人 | 内部对接人员姓名 |
| 接待部门 | 接待部门 |
| 授权门禁点 | 列表形式展示 |
| 有效期 | 通行起止日期 |
| 状态 | 有效（绿色） / 已过期（灰色） / 已撤销（红色） |

**外部人员操作：**

| 操作 | 说明 |
|------|------|
| 新增 | 填写人员信息、选择授权门禁点、设置通行有效期 |
| 编辑 | 修改人员信息或调整授权门禁点和有效期 |
| 撤销权限 | 一键撤销通行权限，状态变为"已撤销"，门禁终端立即同步 |
| 删除 | 删除人员记录 |
| 生成临时二维码 | 为短期访客生成临时通行二维码，有效期绑定 |

### 临时通行凭证

为临时人员生成短期通行凭证：

- **临时二维码**：动态生成，有效期设置后过期自动失效，可打印或发送至手机
- **临时工卡**：分配限定有效期的临时卡号，到期自动从门禁终端清除

### 梯控通行

外部人员的梯控权限与门禁权限统一管理：在授权门禁点的同时可选择电梯楼层权限，设置可通行的目标楼层。

## 3.3.11 人员通行记录

### 实时通行记录

系统提供实时和历史的通行记录查询，以双 Tab 页面呈现：

**今日通行（Tab 1）：**

- **统计卡片**：顶部展示 4 张统计卡片，数字带滚动计数动画
  - 今日总通行人次
  - 正式员工人次
  - 访客人次
  - 外包人员人次
- **分时流量图**：折线/面积图展示今日各时段的出入流量分布，可直观识别早晚高峰
- **通行列表**：每条记录包含序号、姓名、工号、通行平台、门禁点名称、进出方向（进/出）、通行时间（Unix 时间戳格式化）、通行方式（人脸/工卡/二维码）、现场抓拍照片
- **抓拍图预览**：点击"人脸"字段可弹出大图预览现场抓拍照片，与底库照片进行人工比对
- **筛选条件**：关键字搜索（姓名/工号/门禁点）、日期时间范围选择
- **导出**：支持将筛选后的通行记录导出为 Excel (.xls) 文件

**历史通行（Tab 2）：**

- 与今日通行相同的筛选、统计和表格结构
- 默认查询范围为最近一周
- 独立的分时流量图和统计卡片

### 通行记录完整字段

| 字段 | 说明 |
|------|------|
| 序号 | 列表序号 |
| 姓名 | 通行人员姓名 |
| 工号 | 企业工号 |
| 通行平台 | 旷视 / 海康 / 其他 |
| 门禁点名称 | 如"北门入口""2F 办公区东" |
| 进出方向 | 进 (In) / 出 (Out) |
| 通行时间 | 格式化的日期时间 |
| 通行方式 | 人脸 / 工卡 / 二维码 |
| 现场抓拍图 | 门禁终端抓拍的人脸照片，点击可放大 |
| 识别结果 | 比对成功 / 比对失败 / 未比对 |

### 人脸抓拍与底库对比

对于人脸通行记录，系统支持点击"人脸"列查看现场抓拍照片，管理员可在预览窗口中与底库照片进行人工对比，用于核实异常通行（如代刷、尾随等）。

## 3.3.12 梯控管理

### 梯控设备管理

系统支持电梯控制（梯控）的独立管理，与门禁管理共享统一的人员权限体系。

**梯控设备配置：**

| 配置项 | 说明 |
|------|------|
| 梯控点名称 | 如"1#电梯""2#电梯""货梯" |
| 所属空间 | 空间编码 → 楼栋 → 楼层 |
| 可控楼层 | 该电梯可达的楼层列表 |

### 楼层授权（Tab 1）

- 表格展示每个楼层及其已授权用户数量
- 楼层名称以标签形式展示
- 是否限时通行标注（是/否标签）
- 点击"编辑"进入楼层授权对话框：显示当前授权用户（可关闭标签），支持远程搜索添加用户

### 时段控制（Tab 2）

- 按楼层配置通行时段规则
- 每条规则包含：目标楼层、开始时间、结束时间、适用日（周一至周日多选）
- 支持新增、编辑、删除时段规则

### 呼梯记录（Tab 3）

- 查询条件：用户名、日期范围
- 表格字段：用户名、出发楼层、目标楼层、呼叫时间、电梯编号、卡号

### 梯控权限集成

梯控权限与门禁权限使用相同的三级模型：
- 门禁角色中可同时包含门禁组和梯控组
- 默认权限规则中可同时配置门禁权限和梯控权限
- 自动赋权（飞书联动）中入职授权同时下发门禁和梯控权限
- 离职回收时一键同时回收门禁和梯控权限

## 3.3.13 门禁授权工作台（可视化授权）

### 三栏布局授权

系统提供高效的三栏可视化授权工作台（DoorAuth 模块）：

```
┌──────────┬────────────────────────┬──────────┐
│  左栏     │       中栏              │  右栏     │
│ 人员选择  │     权限配置区          │ 已授权    │
│          │                        │ 门禁点    │
│ ┌──────┐ │  大楼通行权限 [穿梭框]    │ 标签云    │
│ │部门树 │ │                        │          │
│ │分组树 │ │  楼层通行权限 [穿梭框]    │ [北门]   │
│ │人员   │ │                        │ [1F电梯] │
│ │搜索  │ │  层内通行权限 [穿梭框]    │ [2F东]   │
│ └──────┘ │                        │ [3F]     │
│          │  时间模板选择            │ ...      │
│          │  保存按钮               │          │
└──────────┴────────────────────────┴──────────┘
```

**左栏 — 人员选择：**
- **部门树 Tab**：按组织架构展开部门树，点击部门加载该部门下所有人员
- **分组树 Tab**：按自定义分组展示
- **人员搜索**：可通过姓名、邮箱、手机号、工号多条件搜索，支持搜索条件展开/折叠

**中栏 — 权限配置：**
- **大楼通行权限**：级联选择器，选择目标楼栋 → 关联的门禁点出现在穿梭框中
- **楼层通行权限**：按楼层配置，选择楼层 → 关联门禁点可穿梭选择
- **层内通行权限**：按区域内门禁点配置
- **时间模板**：每个门禁组可选择：全部时间 / 工作日 / 周末 / 节假日
- **保存按钮**：批量保存所有变更

**右栏 — 已授权门禁点标签云：**

选中人员后，右侧以标签云形式实时展示该人员当前已授权的所有门禁点（通常 40+ 个标签），一目了然。

## 3.3.14 安防分区管理

### 分区概念

安防分区将楼栋/楼层、安防设备（门禁、摄像头、探测器）、以及处置人员绑定为一个安防责任单元。

**分区配置项：**

| 配置项 | 说明 |
|--------|------|
| 分区名称 | 如"1号楼安防分区""核心机房分区" |
| 空间范围 | 关联楼栋和楼层（多选） |
| 关联设备 | 门禁控制器、摄像头、红外探测器、烟感等 |
| 派单角色 | 安保队长 / 值班员 / 监控员（多选） |
| 派单人员 | 支持远程搜索选择具体人员 |
| 启用/禁用 | 开关控制分区是否活跃 |

**临时白名单**：每个分区支持配置临时白名单，允许指定人员在特定时间段内不受该分区门禁策略限制。

## 3.3.15 无感考勤

### 基于门禁的考勤联动

系统利用人脸门禁的通行记录，实现无感考勤（NoTouchCheck）：

- **考勤规则配置**：设置考勤时段、迟到判定规则
- **今日考勤统计**：统计卡片展示总考勤人数、上班准时/迟到人数、下班准时/早退人数
- **考勤记录列表**：包含序号、姓名、部门、邮箱、上班打卡（时间+标签）、下班打卡（时间+标签）
- **异常筛选**：支持按状态筛选（正常/迟到/早退/缺卡）
- **数据导出**：支持导出考勤报表

## 3.3.17 人脸下发与设备同步

### 多厂商设备同步

系统支持同时向旷视（Megvii）和海康（Hikvision）两个主流门禁厂商的设备下发人脸数据：

- **独立追踪**：每张人脸对旷视和海康分别记录推送状态（待推送 / 已推送 / 推送失败）
- **MQTT 实时推送**：人脸照片上传后，通过 MQTT Topic `/iot/action/user/face/push` 实时下发至对应品牌的识别终端
- **失败重试**：推送失败显示具体错误信息，管理员可点击"下发"按钮手动重试
- **设备同步日志**：记录每次同步的系统、方向、同步类型（部门/人员）、时间、返回码和返回消息

### 用户增量同步

通过 MQTT 消息 `/iot/action/user/increment/sync` 触发用户信息的增量同步，确保门禁终端的人员数据与平台保持实时一致。
