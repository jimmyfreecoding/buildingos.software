# 操作说明书（智能楼宇智慧安防管理系统 buildingos.security）

## 一、引言

### 1.1 编写目的
本文档用于说明智能楼宇智慧安防管理系统（buildingos.security）的操作使用方法，帮助安防管理人员快速掌握园区安防监控、告警管理、消防监测、视频巡更、流媒体平台和事件规则引擎等功能的操作。

### 1.2 系统概述
本系统提供覆盖园区安防监控、告警管理、消防监测、视频巡更、流媒体平台、事件规则引擎、人脸轨迹搜索全流程的一体化安防管理解决方案。系统以GIS三维地图为指挥载体，集成视频监控、门禁、周界、消防等多子系统告警数据，实现告警从接收、处理、分发、转派到关闭的全生命周期闭环管理。

### 1.3 适用范围
适用于园区安防监控中心、物业管理办公室、消防控制室等场景的安防管理与应急响应。

---

## 二、运行环境

### 2.1 硬件环境
- 服务端：x86 8核CPU，RAM≥16GB，SSD≥512GB
- 流媒体服务器：支持ZLMediaKit运行，建议独立部署
- 客户端：普通办公PC（i5处理器/8GB内存/256GB存储），分辨率≥1920×1080
- 摄像头：支持RTSP协议的网络摄像头，NVR/DVR需支持GB28181国标协议
- 网络：千兆交换机，支持园区局域网访问

### 2.2 软件环境
- 服务端操作系统：Linux（Ubuntu 22.04）
- Web服务器：Nginx
- 流媒体服务：ZLMediaKit
- 数据库：PostgreSQL 15 / MySQL 8.0 / SQLite
- 消息中间件：MQTT Broker（EMQX/Mosquitto）
- 客户端浏览器：Chrome 90+ / Edge 90+
- 开发环境：Node.js 20.x、Vite、Vue 3、TypeScript 5.x、NestJS 10.x

### 2.3 部署说明
系统采用NestJS微服务架构，独立运行端口3015。前端为Vue 3单页应用，构建产物部署至Nginx。ZLMediaKit流媒体服务需独立部署并配置服务地址。MQTT Broker用于跨子系统消息通信。

用户通过浏览器访问系统URL进入安防管理首页。左侧菜单树按"安防管理"和"运营管理"分组展示功能入口：

**运营管理菜单组**：告警中心、消防应急

点击菜单项切换功能页面，支持页内选项卡切换和独立查询状态维护。

### 3.3 视频监控

视频监控模块以选项卡形式整合监控设备管理和视频实时调阅。

#### 3.3.1 监控设备管理
顶部查询栏支持按设备名称（文本输入）和状态（在线/离线）组合筛选。右侧"新增摄像头"按钮打开表单弹窗，配置设备名称、IP地址、设备类型（枪机/球机/半球）、品牌（海康/大华/宇视/旷视）、所属分组、RTSP地址、PTZ协议等参数。数据表格展示序号、设备名称、IP地址、类型、品牌、所属分组、PTZ协议、在线状态（绿/红标签）、启用状态，每行提供编辑、拉流、删除三个操作按钮。

"拉流"按钮触发流媒体代理添加（addStreamProxy），将摄像头RTSP流注册到ZLMediaKit流媒体服务器返回播放地址。删除设备时同步调用delStreamProxy释放流媒体资源。

### 3.7 告警排班管理

以三个选项卡组织值班人员和排班方案。

#### 3.7.1 人员信息
管理可参与告警值班的人员名单，表格展示姓名、联系方式、邮箱、角色、告警规则和在职状态。支持新增/编辑/删除人员。

#### 3.7.2 特定日期排表
针对特定日期范围（如节假日、重大活动日）设置临时排班，表格展示排班名称、日期范围、负责人（可多选）、设备分组和备注。支持新增/编辑/删除。

#### 3.7.3 周排表
设置按周循环的常规排班，表格展示排班名称、排班人员、设备分组、重复日期（周一至周日标签展示）和时间段。支持新增/编辑/删除。

三种排班方式优先级：特定日期排表 > 周排表 > 人员默认规则。系统处理告警分发时先查特定日期排表，无匹配再查周排表。

### 3.14 事件规则引擎

事件规则引擎通过四个选项卡（合并策略、过滤规则、分发规则、SOP模板）构成完整的告警处理规则管线。

#### 3.14.1 合并策略
定义如何将多条相似告警合并。表格展示策略名称、合并窗口（秒）、合并字段（设备/位置/告警类型/区域多选AND逻辑）、最大合并数和启用开关。新增/编辑时配置策略名称、合并窗口（秒）、合并字段（多选）和最大合并数（1-100）。

#### 3.14.2 过滤规则
定义哪些告警应直接丢弃。表格展示规则名称、过滤条件（标签展示）、优先级和启用开关。新增/编辑时通过条件构建器添加一个或多个条件（字段选择+运算符+值），多条件AND逻辑组合。

#### 3.14.3 分发规则

## 四、业务逻辑说明

### 4.1 告警全生命周期
告警事件经历完整的生命周期：触发→接收→处理/误报→关闭。未接收状态(status=0)可接收确认；已接收状态(status=1)可选择误报标记或处理完成；已处理/已误报状态(status=2/3)归档关闭，仅可查看。

### 4.2 事件规则引擎管线
告警事件依次经过四个规则处理环节：合并策略（同设备/同位置的相似告警在时间窗口内合并为聚合告警，减少告警风暴）→过滤规则（满足过滤条件的告警直接丢弃，不进入后续流程）→分发规则（满足分发条件的告警定向推送到对应岗位/人员，通过多渠道通知）→SOP模板（关联告警类型匹配标准处置程序，指导分步骤规范化处理）。

### 4.3 告警升级机制
系统在告警触发后启动计时器，按告警级别的升级规则配置，在处置时限到达后自动执行超时动作。低级别告警长时间未处理自动升级级别并通知上级；高级别告警超时自动分发到群组并通过多渠道（声音+弹窗+短信+飞书）推送。

### 4.4 排班优先级裁决
告警分发时的排班匹配优先级：特定日期排表 > 周排表 > 人员默认规则。系统先查当天是否有特定日期排班安排，无匹配再查周排表（按当天星期几匹配），最后使用人员默认告警规则。

### 4.5 合并策略逻辑
合并引擎按配置的时间窗口（秒）和合并字段维度（设备/位置/告警类型/区域多选AND），将时间窗口内所有字段值都相同的多条告警合并为1条聚合告警。原始告警完整JSON附加在聚合告警的展开详情中，最大合并数控制聚合上限。例如某摄像头30秒内连续触发5次"异常行为"告警，配置同设备合并策略（窗口60秒/字段为"设备"/最大合并数10），5条告警被合并为1条。

### 4.6 流媒体代理管理
视频监控设备的"拉流"操作调用ZLMediaKit的addStreamProxy接口，将摄像头的RTSP流地址注册为流媒体代理，返回可直接播放的HTTP-FLV/WebSocket-FLV/RTMP/HLS播放地址。删除设备时同步调用delStreamProxy接口释放流媒体服务器资源，确保不产生僵尸推流。

### 4.7 白名单自动过期
系统按白名单配置的有效期（开始日期至结束日期）自动判断状态：当前日期在有效期内显示"有效"（绿色标签），超过结束日期自动显示"已过期"（红色标签），告警检测逻辑自动跳过已过期的白名单记录。

## 五、常见问题

### 5.1 视频无法播放
**现象**：点击摄像头"视频"或"拉流"后播放器黑屏无画面。
**排查**：确认摄像头RTSP地址正确且网络可达；检查ZLMediaKit流媒体服务是否正常运行；确认摄像头编码格式为H.264（部分旧设备H.265需转码模板支持）；检查浏览器是否支持WebSocket。

### 5.2 流媒体服务异常
**现象**：流媒体平台状态页显示服务离线。
**排查**：确认ZLMediaKit服务进程正在运行；检查服务地址和端口配置是否正确；确认服务器防火墙允许HTTP/RTMP/RTSP/WebSocket端口通信。

### 5.3 告警未收到声音提醒
**现象**：告警触发后无声音提示。
**排查**：确认告警声音策略中声音告警开关已开启；检查音量设置不为0；确认该告警级别的声音绑定已启用且声音文件存在；检查浏览器是否允许音频自动播放（Chrome需用户先与页面交互）。

### 5.4 合并告警无法展开查看原始记录
**现象**：告警聚合页面行展开无内容。
**排查**：确认该聚合告警确实由合并策略生成（非原始告警）；检查合并策略是否被禁用导致告警未被合并；确认合并策略的合并字段配置与实际告警数据字段一致。

### 5.5 白名单配置后告警仍然触发
**现象**：对某设备配置白名单后该设备仍产生告警。
**排查**：确认白名单有效期包含当前日期（过期白名单不生效）；检查白名单对象类型与告警对象类型是否匹配；确认白名单适用范围包含告警发生位置。

### 5.6 人脸轨迹搜索无结果
**现象**：上传人脸照片搜索后返回空结果。
**排查**：确认照片质量（清晰度、光线、人脸占比）；尝试降低相似度阈值扩大匹配范围；确认查询时间范围覆盖目标人员的活动时间段；检查外部人脸识别API（旷视/海康）是否正常运行。

### 5.7 GB28181设备离线
**现象**：国标设备列表中设备显示离线状态。
**排查**：确认设备NVR/DVR的GB28181配置正确（SIP服务器地址/端口/域/设备ID）；检查SIP信令服务是否正常运行；确认设备网络可达SIP服务器端口。
