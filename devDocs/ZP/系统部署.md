# 系统部署方案

## 一、部署架构概述

BuildingOS AI 智慧楼宇操作系统支持多种部署拓扑，覆盖从单机试点到多节点高可用集群、从纯云端到边云协同的完整场景。所有部署方式共享同一套容器镜像体系与服务口径，可根据甲方实际 IT 基础设施规模灵活选择。

### 部署方式矩阵

| 部署方式 | 节点规模 | 高可用 | 适用场景 |
|----------|----------|--------|----------|
| Docker Compose 单机 | 1 节点 | 否 | 小园区试点、开发测试、边端独立部署 |
| Docker Swarm 集群 | 3-5 节点 | 支持（PG/EMQX/TDengine 均可集群化） | 中型园区、私有云部署 |
| K3s 轻量集群 | 1-3 节点 | 支持 | 大中型园区标准化部署（推荐） |
| K8s 标准集群 | 2-5 节点 | 支持 | 大型园区、混合云部署 |
| 边端独立部署 | 1 节点 | 否 | 园区侧本地闭环运行 |

## 二、容器化部署

### 2.1 容器运行时

系统所有服务均基于 Docker 容器化打包，镜像统一托管于容器镜像仓库，支持以下运行时环境：

- **Docker Engine** 24.x+（单机 / Swarm 模式）
- **K3s** v1.31+（轻量 Kubernetes 发行版）
- **标准 Kubernetes** 1.30+

### 2.2 镜像管理

- 所有生产镜像统一存储在私有容器镜像仓库
- 支持离线环境下的镜像导出/导入（`docker save` / `docker load`）
- 镜像构建采用 CI/CD 自动化流水线，代码推送即自动构建并推送至镜像仓库
- 服务更新策略：拉取新镜像 → 滚动重建容器 → 零停机上线

### 2.3 核心服务容器

| 服务 | 技术栈 | 用途 |
|------|--------|------|
| **Web 前端** | Vue.js 3 + Nginx | 管理后台、H5 移动端、会议室 Pad、墙装屏 |
| **Backend 后端** | NestJS (Node.js) | 业务逻辑、API 网关、用户认证、空间管理 |
| **PostgreSQL** | PostgreSQL 16 + TimescaleDB + pgvector | 业务数据库（空间、设备、用户、通行记录等） |
| **TDengine** | TDengine 3.3 | 物联网时序数据库（设备遥测、告警事件） |
| **EMQX** | EMQX 5.8 | MQTT 消息代理（设备数据接入与下发） |
| **Node-RED** | Node-RED 4.x | 低代码流程编排（联动规则、场景自动化） |
| **ZLMediaKit** | ZLMediaKit | 流媒体服务（视频直播、回放） |
| **Go-Bridge** | Go | MQTT → TDengine 数据桥接 |

## 三、单机部署（Docker Compose）

### 3.1 架构说明

适用于单服务器场景，通过 Docker Compose 一键编排全部服务容器。所有服务运行于同一台物理机或虚拟机，通过 Docker Bridge 网络内网互通，数据库端口不对外暴露。

### 3.2 服务拓扑

```
┌─────────────────────────────────────────────────┐
│                    服务器                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐       │
│  │ Nginx:80 │  │Backend   │  │PostgreSQL│       │
│  │ (前端)   │  │:3001     │  │(内部)    │       │
│  └──────────┘  └──────────┘  └──────────┘       │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐       │
│  │ EMQX     │  │TDengine  │  │Node-RED  │       │
│  │:1883/8083│  │(内部)    │  │x3 实例   │       │
│  └──────────┘  └──────────┘  └──────────┘       │
│  ┌──────────┐  ┌──────────┐                      │
│  │ZLM-      │  │Go-Bridge │                      │
│  │MediaKit  │  │          │                      │
│  └──────────┘  └──────────┘                      │
└─────────────────────────────────────────────────┘
```

### 3.3 部署特点

- **一键启动**：`bash deploy.sh` 自动拉取镜像并启动全部服务
- **HTTPS 自动切换**：配置域名后自动启用 Let's Encrypt SSL 证书
- **数据持久化**：PostgreSQL、TDengine、Node-RED 数据均通过 Docker Volume 持久化存储
- **资源限制**：每个容器均设置 CPU/内存上限，防止单服务耗尽主机资源
- **健康检查**：全部服务配置 Docker Healthcheck，异常自动重启
- **安全隔离**：数据库端口（PG 5432、TDengine 6030/6041）仅 Docker 内网可访问

### 3.4 适用场景

- 单个园区/楼宇的独立部署
- 边端节点（与云端通过 PG 逻辑复制 + MQTT Bridge 协同）
- 开发测试环境

## 四、高可用集群部署

### 4.1 Docker Swarm 集群（3-5 节点）

基于 Docker Swarm 编排的多节点集群方案，支持服务多副本调度与数据库集群化。

**节点角色分工：**

| 角色 | 节点 | 部署服务 |
|------|------|----------|
| data | Node1 | PostgreSQL、TDengine、EMQX、Redis |
| compute | Node2-3 | Web 前端（2 副本）、Backend（2 副本） |

**高可用增强（可选叠加）：**

| 组件 | 单机模式 | HA 模式 |
|------|----------|---------|
| PostgreSQL | 1 实例 | 3 节点 repmgr 主从 + Pgpool-II 连接池 |
| EMQX | 1 实例 | 3 节点静态发现集群 |
| TDengine | 1 实例 | 3 节点集群 |
| Web/Backend | 1 副本 | 2-3 副本（跨节点调度） |

### 4.2 K3s 集群（推荐标准化方案）

K3s 是当前项目的最新标准化部署范式，基于轻量 Kubernetes 发行版，兼顾生产级高可用与运维简便性。

**3 节点 Phase2 集群架构：**

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│   Master     │  │   Worker 1   │  │   Worker 2   │
│   Node 1     │  │   Node 2     │  │   Node 3     │
├──────────────┤  ├──────────────┤  ├──────────────┤
│ pgpool       │  │ PG replica 1 │  │ PG replica 2 │
│ TDengine 1   │  │ TDengine 2   │  │ TDengine 3   │
│ EMQX 1       │  │ EMQX 2       │  │ EMQX 3       │
│ Web          │  │ Web          │  │              │
│ Backend      │  │ Backend      │  │              │
│ Node-RED x2  │  │              │  │              │
└──────────────┘  └──────────────┘  └──────────────┘
```

**高可用设计：**

| 能力 | 实现方式 |
|------|----------|
| PostgreSQL 主从 | repmgr 2 副本 + pgpool 读写分离，自动故障转移 |
| TDengine 集群 | 3 副本 StatefulSet + Headless Service，自动选主 |
| EMQX 集群 | 3 副本 + K8s DNS 自动发现，MQTT 会话跨节点共享 |
| 服务自愈 | Pod 异常自动重建，节点故障自动漂移 |
| 存储高可用 | Longhorn 分布式块存储，PVC 跨节点动态供给 |
| 滚动更新 | Deployment 滚动升级，零停机发布 |

### 4.3 标准 K8s 集群

支持标准 Kubernetes 集群部署，适用于已有 K8s 基础设施或混合云场景。

- **2 节点 Demo**：CloudNativePG 数据库集群 + NFS 共享存储
- **3-5 节点生产**：PostgreSQL 2 副本 StatefulSet + Redis 3 副本 + EMQX 3 副本
- **自动扩缩**：Web/Backend 支持 HPA 水平自动扩缩

## 五、边云协同部署

### 5.1 架构概述

系统原生支持"一云端 + 多边端"的分布式部署架构。云端部署于甲方私有云/中心机房，边端部署于各园区本地。

```
                ┌──────────────────────────┐
                │    云端 K3s 集群           │
                │  (PG主库 / TDengine /     │
                │   EMQX / Node-RED / Web)  │
                └─────┬──────────┬──────────┘
                      │          │
           ┌──────────┘          └──────────┐
           ▼                                ▼
  ┌─────────────────┐            ┌─────────────────┐
  │ 边端 A (园区1)   │            │ 边端 B (园区2)   │
  │ PG 只读副本     │            │ PG 只读副本     │
  │ EMQX + TDengine │            │ EMQX + TDengine │
  │ Node-RED + ZLM  │            │ Node-RED + ZLM  │
  └─────────────────┘            └─────────────────┘
```

### 5.2 数据流向

| 方向 | 内容 | 机制 |
|------|------|------|
| 云 → 边 | 空间结构、设备主数据、联动规则 | PostgreSQL 逻辑复制（Publication/Subscription） |
| 边 → 云 | 设备状态、关键事件、聚合摘要 | EMQX MQTT Bridge |
| 云 → 边 | 代码/镜像/流程更新 | 私有镜像仓库同步 |

### 5.3 边端自治

- 边端可在断网情况下独立运行 24-72 小时
- 本地 EMQX + Node-RED + TDengine 保持 IoT 闭环
- 恢复连接后自动增量同步状态数据至云端

## 六、数据库选型

### 6.1 数据库清单

| 数据库 | 类型 | 版本 | 许可 | 用途 |
|--------|------|------|------|------|
| **PostgreSQL** | 开源关系型数据库 | 16.x | PostgreSQL License（类 BSD） | 业务主库（用户、空间、设备、通行、会议等） |
| **TDengine** | 开源时序数据库 | 3.3.x | AGPL v3 / 商业许可 | 物联网时序数据（设备遥测、能耗、告警事件） |

### 6.2 为什么选择开源数据库

1. **PostgreSQL**：全球最先进的开源关系型数据库，支持 ACID 事务、丰富扩展生态（TimescaleDB 时序扩展、pgvector 向量检索、PostGIS 空间计算），被国内外大量政企项目采用
2. **TDengine**：国产开源时序数据库，专为物联网场景优化，写入性能比通用数据库高 10 倍以上，存储压缩比达 10:1，支持集群与流式计算
3. 两者均为成熟的开源产品，有活跃的社区支持和商业支持选项，数据存储格式公开透明，不存在厂商锁定风险

### 6.3 高可用方案

| 数据库 | 高可用方案 | RPO | RTO |
|--------|------------|-----|-----|
| PostgreSQL | repmgr 流复制 + pgpool 读写分离，2-3 副本 | ≈0（同步复制） | < 30s |
| TDengine | 原生集群（3 节点），自动选主与数据分片 | ≈0 | < 10s |

## 七、运维与扩容

### 7.1 监控与告警

- 容器健康检查：Docker Healthcheck / K8s Liveness & Readiness Probe
- 日志收集：标准输出 + 持久化日志卷
- 可选集成：Grafana + Prometheus 监控面板

### 7.2 水平扩容

| 服务 | 扩容方式 |
|------|----------|
| Web / Backend | 增加容器副本数（Docker Compose `--scale` 或 K8s HPA） |
| EMQX | 增加集群节点，自动发现加入 |
| TDengine | 增加集群节点，数据自动重分布 |
| PostgreSQL | 增加只读副本，pgpool 负载均衡 |

### 7.3 垂直扩容

- 调整容器 CPU/内存资源限制
- 扩展持久化存储卷容量
- 无状态服务（Web/Backend）可无感扩缩

### 7.4 备份与恢复

- PostgreSQL：支持 pg_dump 逻辑备份 + WAL 连续归档
- TDengine：支持 taosdump 全量/增量备份
- 容器数据卷：可结合宿主机文件系统快照

---

## 八、安全合规

### 8.1 网络安全

- 数据库端口不对外暴露，仅容器内网访问
- MQTT Broker 支持 TLS/SSL 加密传输
- Web 端支持 HTTPS（Let's Encrypt 或自有证书）
- API 接口基于 JWT Bearer Token 认证

### 8.2 数据安全

- 所有数据库密码通过环境变量/Secret 注入，不硬编码于配置文件
- 支持私有镜像仓库，不依赖互联网拉取镜像
- 边云通道建议通过 VPN 专线或加密隧道连接

## 九、部署方式对比

| 特性 | Docker Compose 单机 | Docker Swarm 集群 | K3s 集群 | K8s 集群 |
|------|---------------------|---------------------|-----------|-----------|
| **最小节点数** | 1 | 3 | 1-3 | 2+ |
| **容器编排** | Compose | Swarm | Kubernetes | Kubernetes |
| **自动故障转移** | 否 | 部分（Swarm 调度） | 是 | 是 |
| **水平扩缩** | 手动 | 手动 | 自动（HPA） | 自动（HPA） |
| **滚动更新** | 否（需停机） | 支持 | 支持 | 支持 |
| **存储方案** | 本地卷 | 本地卷/NFS | Longhorn / local-path | CSI 驱动（NFS/云盘） |
| **运维复杂度** | 低 | 中 | 中 | 高 |
| **适用场景** | 试点/边端 | 中型园区 | 大中型园区 | 大型/混合云 |
| **生产验证** | 已上线 | 参考方案 | 推荐标准方案 | 参考方案 |
