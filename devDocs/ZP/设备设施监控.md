# 3.6 设备设施监控（IBMS）

## 需求概述

本系统提供覆盖设备设施全生命周期管理的智能楼宇集成监控（IBMS）解决方案。以 Node-RED 可视化流程编排引擎为组态核心，集成 16 类物联网设备的统一管理、实时状态监控、3D/2D 室内地图定位、环境质量综合分析、设备运行趋势统计、设备在线率监控和设备告警自动转工单等能力，实现园区设备设施的"可知、可视、可控、可管"。

---

## 3.6.1 整体架构

### 模块总览

设备设施监控系统包含以下功能模块，通过设备管理和楼宇智控两大菜单入口组织：

**设备管理**——网关管理、物联网设备、设备分组、IP 摄像头、IP 设备、设备地图（点位标注）、设备场景（自动化策略）、设备巡检（IoT 巡检 + 会议室巡检）、设备告警、设备日志。

**楼宇智控**——按设备类型分为电梯、门禁、照明、调光照明、空调、人感、窗帘、环境、烟感、水浸、智能平板、厕位、电量传感器、排风、新风共 15 个子模块，每个模块提供空间树筛选、设备卡片网格、批量控制和地图查看。

**组态仪表板**——设备总览大屏，按设备类型分选项卡展示离线/故障设备的实时状态。

**运营看板**——环境监测看板（8 项指标 + 趋势图 + 传感器详情表）。

### 技术架构

系统以 MQTT 协议为设备通信骨干，设备通过边缘网关接入平台，状态数据经 MQTT 主题实时推送至前端。前端通过 Pinia 状态管理（StatusListStore）维护全量设备实时状态，5 秒周期轮询刷新。Node-RED 流程编辑器部署于每个边缘网关上，通过 iframe 嵌入管理后台，实现零代码的可视化自动化流程编排。

系统支持 16 种物联网设备类型：照明、调光照明、空调、空气净化器、排风扇、窗帘、空气传感器、烟感传感器、人体传感器、电量传感器、水量传感器、水浸传感器、厕位传感器、智能平板、AI 摄像头传感器和边缘网关。

## 3.6.2 组态仪表板（设备总览）

### 功能入口

运营管理 → 仪表板

### 功能描述

组态仪表板是设备设施统一监控的总览大屏，提供全量设备的在线/离线状态统计和按设备类型的分类监控。

#### 统计卡片

页面顶部展示四个统计卡片，实时反映全局设备状态：

**总设备数**——系统当前纳管的全部物联网设备总数，以动画计数器展示数字变化。

**在线正常设备数量**——当前状态为在线的设备总数，反映当前可用设备规模。

**离线故障设备数量**——当前状态为离线或告警的设备总数，以红色突出显示，帮助管理人员快速定位异常。

**在线正常比例**——在线设备数占总设备数的百分比，直观反馈全局设备健康度。

四个卡片数据来源于 MQTT 实时状态推送，每 5 秒自动刷新，无需手动查询。

#### 按设备类型分类监控

统计卡片下方以选项卡形式按 16 种设备类型分类展示离线/故障设备明细。每种设备类型一个选项卡，切换后显示该类型下所有异常设备的列表。表格列包含：设备名称、所属网关、空间分区（属地）、楼层、区域和错误信息（描述离线或告警的具体原因，如"通信超时""传感器故障"等）。

此设计使得运维人员可以快速按设备类型聚焦异常，例如发现"空调"选项卡离线设备增多，可立即判断空调系统存在共性问题。

#### 异常厕位预警

在厕位传感器选项卡中提供"异常厕位预警"按钮。点击后通过 MQTT 主题 `/iot/wcsensor/nobody/get` 查询所有厕位的占用状态，弹出对话框以表格展示：属地、楼层、厕所名称、厕位编号、设备 ID 和当前状态。用于检测是否存在长时间无人但传感器显示占用的异常厕位（可能为传感器故障或人为误报）。

## 3.6.3 Node-RED 可视化组态引擎

### 功能入口

设备管理 → 网关 → 编辑流程

### 功能描述

系统以 Node-RED 作为组态搭建和自动化编排的核心引擎，替代传统的拖拽式组态工具。每个边缘网关上运行独立的 Node-RED 实例，用户可通过管理后台直接打开对应网关的 Node-RED 流程编辑器。

#### 网关管理

网关管理页面以楼层空间树（左侧）和网关卡片网格（右侧）的布局展示所有边缘网关。每个网关卡片显示网关名称（IP:端口）、空间位置路径和网关图片。卡片提供两个操作按钮：

**浏览器打开**——在新浏览器窗口中直接打开该网关的 Node-RED 管理界面（`http://{ip}:{port}`），适用于需要完全访问 Node-RED 全部功能的场景。

**编辑流程**——在当前页面内通过全屏 iframe 嵌入 Node-RED 编辑器（路径格式为 `/devices/nodered?url=http://{host}:{port}/nodered/{ip}/{port}/`），无需离开管理后台即可编排流程，提升操作效率。

#### 网关配置

新增或编辑网关时配置以下参数：
- **网关类型**：单选——边缘网关（连接终端设备）或主网关（汇聚边缘网关数据）
- **MAC 地址**：必填，网关的唯一硬件标识
- **IP 地址**：必填，使用 IP 地址输入组件，支持格式校验
- **端口**：网关 HTTP 服务端口号
- **使用用户名密码**：开关控制，开启后显示用户名和密码输入框（用于 Node-RED 的 HTTP Basic Auth 认证）
- **描述**：文本域（10 行），记录网关的安装位置、用途等补充信息

#### Node-RED 组态能力

Node-RED 流程编辑器提供以下组态搭建能力：

**可视化流程编排**——通过拖拽节点并连线的方式构建自动化流程。内置丰富的节点类型（MQTT 输入/输出、HTTP 请求、函数处理、时间触发、数据库读写、Modbus/TCP 协议适配等），覆盖设备数据采集、处理、转发和联动控制全场景。

**零代码配置**——每个节点的参数通过表单配置而非编码完成，例如 MQTT 节点只需填写 Broker 地址、端口和订阅主题，函数节点提供可视化的数据映射和转换界面。

**设备间的拓扑关系展示**——通过连线直观展示设备间的数据流向和控制关系。例如：烟感传感器 → MQTT 输入节点 → 条件判断节点 → MQTT 输出节点（控制消防广播） → HTTP 请求节点（调取摄像头画面），整个联动逻辑一目了然。

**流程版本管理**——Node-RED 内置流程的部署、启用/停用和版本回滚能力。每次部署自动保存流程快照，可在需要时回退至历史版本。

**动态数据流效果**——流程部署运行后，节点间的连线实时展示数据包的流转动画，操作人员可以直观看到数据在各节点间的传输状态（包括数据内容和传输速率）。

## 3.6.4 空间地图设备定位

### 功能入口

设备管理 → 地图

### 功能描述

空间地图模块以 AirocovMap 三维室内地图引擎为底座，将设备在楼层平面图上的实际位置以图标标注，支持设备的交互式点位管理和实时状态可视化。

#### 多楼层切换

页面右侧表单提供楼层下拉选择器，加载当前空间的所有楼层列表。选择楼层后，地图自动切换到对应楼层的平面图，并加载该楼层的设备点位数据。

#### 设备类型筛选

设备类型下拉选择器列出 12 种支持地图标注的设备类型：照明、调光照明、空调、窗帘、空气传感器、烟感传感器、人体传感器、电量传感器、水量传感器、水浸传感器、厕位传感器、智能平板和 AI 摄像头。选择类型后，左侧地图加载该类型设备图标，右侧面板展示该类型所有设备的点位管理列表。

#### 图例展示

地图左上方展示当前设备类型的图例，每种设备类型有多种状态图标（如照明"开"绿色图标、"关"灰色图标、"离线"红色图标），颜色与图标严格对应，方便看图识状态。

#### 设备点位管理

右侧"位置管理"选项卡以列表展示当前类型的全部设备，每行包含设备图标、设备名称和操作按钮：
- **添加**：设备尚未在平面图上标记位置时显示"添加"按钮，点击后进入放置模式
- **调整**：设备已有位置标记时显示"调整"按钮，点击后可拖动图标到新位置
- **删除**：移除设备在平面图上的位置标记

#### 交互式点位放置

点击"添加"或"调整"后，用户在地图上点击目标位置即可放置设备标记。放置后弹出确认对话框，包含保存和取消选项。保存后设备坐标（X、Y、Z）写入后端，后续地图加载时自动定位到该位置。

#### 设备实时状态可视化

通过 MQTT 订阅各设备类型的实时状态数据，地图上的设备图标根据当前状态动态切换。例如照明设备：状态为"on"时显示绿色开灯图标，状态为"off"时显示灰色关灯图标，状态为"offline"时显示红色离线图标。空气传感器设备图标的 Tooltip 中直接显示当前温度读数，点击标记可打开设备详情抽屉。

#### 地图交互功能

地图支持以下交互操作：
- **自由拖拽**——鼠标拖拽平移地图视野
- **无级缩放**——鼠标滚轮缩放地图，从整层鸟瞰到局部细节平滑过渡
- **3D/2D 模式切换**——在三维视图和二维平面图之间一键切换
- **指北针控件**——地图叠加指北针图标，辅助方向定位
- **点击模型识别**——点击楼层平面、房间、区域、墙壁、标识等不同类型的模型元素均可获取对应信息

#### 搜索定位

空间名称和设备名称的搜索定位功能集成在空间树和设备列表中。在空间树中点击某个空间节点，右侧设备列表自动过滤该空间下的设备。在设备列表中选择某个设备并点击"查看"（或在地图模式下点击"添加/调整"），地图自动飞行定位到该设备所在位置，实现从名称到空间位置的快速导航。

## 3.6.5 环境分析

### 功能入口

运营管理 → 运营看板 → 环境监测

### 功能描述

环境监测看板以仪表卡片、趋势图和详情表三层结构，全面展示园区各区域的环境质量数据。

#### 八项环境指标概览

页面顶部以八个彩色卡片展示当前环境核心指标：

**温度**（蓝色，单位 °C）——当前环境平均温度，来源于空气传感器的温度通道。

**湿度**（绿色，单位 %）——当前环境平均相对湿度，来源于空气传感器的湿度通道。

**AQI**（绿色，无量纲）——空气质量综合指数，综合 PM2.5、CO2、TVOC 等指标计算得出。

**PM2.5**（橙色，无量纲）——细颗粒物浓度指数，来源于空气传感器的 PM2.5 通道。

**CO2**（紫色，单位 ppm）——二氧化碳浓度，反映空间通风状况和人员密度，>800ppm 时提示注意通风。

**TVOC**（粉色，单位 mg/m³）——总挥发性有机物浓度，反映装修污染和空气清洁度。

**噪音**（黄色，单位 dB）——环境噪音分贝值。

**舒适度**（蓝色，单位 分）——综合温度、湿度、AQI、PM2.5、CO2、TVOC 和噪音七项指标加权计算的舒适度评分。评分等级：舒适（85 分以上）、良好（70 分以上）、一般（55 分以上）、较差（55 分以下）。舒适度评分帮助物业管理人员量化室内环境品质。

每个卡片以大幅数字展示当前值，下方展示辅助文字或趋势描述。

#### 各区域温度趋势图

环境指标卡片下方展示 ECharts 折线图，以小时为粒度展示各区域（如 A 栋、B 栋、C 栋）的温度 24 小时变化趋势。不同区域以不同颜色的平滑曲线表示，曲线下方为渐变半透明填充区域。图表支持鼠标悬浮显示详细 tooltip（区域名称 + 时间点 + 温度值），支持响应式尺寸自适应。

#### 环境传感器详情表

页面底部以数据表格展示各区域环境传感器的详细读数：

| 列 | 内容 |
|---|---|
| 区域 | 传感器所在位置名称 |
| 温度 | 带颜色圆点（高温 >26°C 红色，正常蓝色），显示 °C |
| 湿度 | 绿色圆点 + 百分比 |
| PM2.5 | 数值 + 进度条（最大值 75，>40 橙色警告色，≤40 绿色正常色） |
| CO₂ | 数值 + 进度条（最大值 2000，>800 橙色警告色，≤800 绿色正常色） |
| 噪音 | 分贝值 |
| 状态 | 彩色标签（正常/告警/异常） |

PM2.5 和 CO2 的进度条加数值展示方式，使得超标程度一目了然，帮助运维人员快速判断需要重点关注的区域。

## 3.6.6 设备运行分析

### 功能入口

楼宇智控 → 各设备类型子模块

### 功能描述

楼宇智控模块按设备类型分为 15 个独立子模块，每个模块提供统一的功能框架：空间树筛选 → 设备卡片网格 → 批量控制 → 地图查看。以照明模块为例：

#### 空间树筛选

左侧空间树以"楼栋 → 楼层 → 区域"三级结构展示当前空间的层级关系，支持节点展开和高亮选中。点击某个节点后右侧加载该空间范围内的对应类型设备。面包屑导航条实时显示当前选中的空间路径。

#### 设备卡片网格

右侧以响应式卡片网格展示设备。每张设备卡片（DeviceCard 组件）展示：
- 设备图标（根据设备类型和当前状态动态切换）
- 设备名称
- 设备状态信息（开/关/在线/离线/告警）
- 所属网关和位置

卡片实时响应 MQTT 状态更新，设备开关状态变化后卡片图标和文字立即刷新。无设备时展示空状态提示。

#### 批量控制

工具栏提供"全开"和"全关"按钮，按钮标签动态显示当前空间范围（如"3F 全开""3F-A区 全关"）。点击后通过 MQTT 向当前空间范围内所有同类型设备发送统一的开/关指令，实现一键批量控制。适用于下班后全楼层关灯、上班前全楼层开空调等场景。

#### 地图查看

点击"地图查看"按钮，打开 80% 宽度的右侧抽屉，内嵌 MapPanel 组件，以平面图标注当前空间范围内的该类设备位置和设备状态。地图支持点击设备标记查看详情，结合空间位置快速定位指定设备。

#### 其他楼宇智控子模块

门禁模块提供门禁设备的状态监控和远程开关控制。空调模块除批量开关外，还展示各空调设备的运行模式（制冷/制热/送风/除湿）、设定温度和当前室温，支持远程调温。环境模块以空气传感器数据为主，展示温度、湿度、PM2.5、CO2 等多通道读数，页面顶部显示当前空间的平均温度。

人感模块展示人体传感器状态（有人/无人），提供空间人员活动热力感知。窗帘模块支持窗帘的批量升降和百分比开合控制。烟感和水浸模块以告警监控为主，传感器触发时设备卡片高亮变红。

## 3.6.7 设备在线率（设备分组与状态监控）

### 功能入口

设备管理 → 设备分组

### 功能描述

设备分组管理允许用户自定义设备分组，并按分组维度监控设备的在线/离线状态。

#### 分组列表

表格展示所有已创建的分组，包含分组名称、创建者、分组类型（以标签区分"传感分组"和"控制分组"）、设备数量（可排序）、状态和创建时间。每行提供编辑和删除操作。

#### 分组编辑器

新增或编辑分组时弹出编辑弹窗，配置以下字段：
- **分组名称**：文本输入
- **创建者**：自动填充或手动输入
- **创建时间**：日期时间选择器
- **状态**：下拉选择启用/禁用
- **分区**：下拉选择空间分区
- **楼层**：下拉选择楼层
- **区域**：下拉选择区域
- **类型**：下拉选择分组类型（传感分组 / 控制分组）
- **计算公式**：文本输入，用于对传感分组内的设备数值进行聚合计算（如"平均值""求和"）
- **MQTT 主题**：文本输入，分组关联的 MQTT 通信主题
- **选择设备**：穿梭框（Transfer）组件，左侧为可用设备列表，右侧为已选设备列表，支持搜索过滤和批量选择

设备分组创建后，可在组态仪表板或其他页面中按分组维度查看设备的整体在线率和运行状态。

#### 物联网设备台账

物联网设备列表页面（设备管理 → 物联网设备）以空间树 + 设备表格的经典布局展示全量设备台账。表格展示：设备 ID、在线状态（绿色/红色圆点）、设备名称、设备类型、网关位置（完整空间路径）、通信协议和通道信息、设备开关状态（开关组件或忙闲标签）、激活时间和描述。每行提供"详细"按钮，点击后打开右侧抽屉展示设备详细信息。

**设备详情抽屉**包含四个子卡片：
- **设备状态卡片**——根据设备类型和当前状态渲染不同的设备图标和状态文字
- **设备信息卡片**——描述列表展示设备名称、设备编号、厂商、设备 ID、协议、通信方式、网关名称、楼层、区域、产品类型和 IoT 类型
- **设备配置卡片**——展示和编辑设备类型的特定配置参数，如空调外机编号、烟感灵敏度、人体传感器模式和延时
- **数据采集与指令下发卡片**——实时显示设备传感器的数据采集值，以及该设备支持的控制指令列表，通过 MQTT 下发指令

#### 实时在线状态监控

系统的在线/离线监控基于 MQTT 全局状态订阅机制。前端启动时即订阅 `/iot/status/#` 通配符主题，所有设备的实时状态数据汇聚到 StatusListStore（以"网关MAC-设备编码"为键索引），各页面组件从中读取对应设备的状态数据。状态更新延迟通常 <1 秒，实现准实时的在线/离线判断。

## 3.6.8 设备报警规则与工单联动

### 功能入口

设备管理 → 告警（设备告警日志）

### 功能描述

设备告警模块记录设备上报的异常事件，并支持将告警一键转为工单，实现告警 → 工单的闭环联动。

#### 告警日志查询

查询栏支持按关键字（告警内容模糊搜索）和时间周期（日期范围选择器）筛选设备告警。

告警数据表格支持行展开（expand），展开后展示告警详情：告警类型、设备 ID、日志信息（以红色圆点高亮）、告警代码。

表格行展示：告警类型、设备 ID、日志内容（红色圆点 + 告警消息）、设备全名、告警代码和告警时间（Unix 时间戳转换显示）。

#### 告警转工单

每条告警行提供"转工单"按钮。点击后，系统基于告警信息（设备名称、告警类型、告警内容、告警位置）自动填充工单创建表单的对应字段，生成一条报修来源为"告警"的工单，并按照分配规则自动指派处理人和处理小组。此功能将设备告警与工单系统无缝打通，设备异常触发告警后一键生成可追踪的维修工单，避免告警被遗漏。

#### 设备场景自动化（策略引擎）

设备场景模块（设备管理 → 场景）补充了告警的自动化处理能力，支持两种策略模式：

**触发器（定时策略）**——基于 Cron 表达式定时执行控制动作。例如"工作日 8:00 全楼开灯""周末 18:00 关闭公共区域空调"。触发器表格展示策略标题、Cron 表达式、启用开关和任务时间模拟（CronParser 解析展示未来 5 次执行时间），支持新增/编辑/删除。

**条件策略**——基于设备点位值触发动作。例如"当 3F 温度 > 30°C 时，自动开启该区域空调并生成一条告警""当烟感传感器报警值为 1 时，自动关闭该区域新风阀门"。条件策略与定时策略共同构成设备控制的自动化规则引擎。

两种策略的执行日志均可追溯：定时策略日志记录执行场景、执行描述、执行内容（MQTT 下发指令）、执行主题和执行时间；条件策略日志记录策略名称、执行内容、执行主题和执行时间。

## 3.6.9 设备巡检

### 功能入口

设备管理 → 巡检

### 功能描述

设备巡检模块包含物联网设备巡检和会议室设备巡检两个子功能，提供自动化的设备健康检查能力。

#### 物联网设备巡检

巡检页面提供开始楼层和结束楼层的范围选择器，点击"开始巡检"后系统按楼层顺序逐一检查各层设备状态。巡检过程通过 MQTT 向每层设备发送状态请求，异步等待数据返回（每层间隔 120 秒，设备状态准备时间 5 秒），结果以卡片形式逐层展示。每层显示该层设备的总览：正常设备数量、离线设备数量和告警设备数量。异常设备以红色高亮显示具体错误信息。

巡检支持跳过无设备楼层（已排除会议室不存在的楼层如顶层、设备层等）。巡检完成后支持"打印 PDF"导出巡检报告，包含每层设备的状态汇总和异常明细。

#### 会议室设备巡检

会议室巡检专门针对会议室场景的设备健康检查，按会议室分组展示。每个会议室显示 5 类设备的状态：门牌（智能平板）、人体传感器、照明、空调和空气传感器。状态以颜色编码：绿色（正常）、黄色（有人或使用中）、红色（离线/故障）、灰色（无人）。

支持特殊异常检测逻辑：如照明和空调同时离线则判定为会议室断电；门牌状态与人体传感器状态不匹配则标记为异常（可能存在传感器故障）。巡检结果支持打印 PDF 导出。

## 3.6.10 设备日志

### 功能入口

设备管理 → 日志

### 功能描述

设备日志记录所有针对物联网设备的操作行为，提供完整的操作审计链路。

#### 查询与筛选

查询栏支持按设备名称（关键字搜索）、空间范围（级联选择器，按空间层级选择）和时间周期（日期范围选择器）筛选操作日志。

#### 日志表格

每行支持展开，展开后展示操作详情：执行指令内容（sourceContent，即下发的 MQTT 消息体）、执行者（sourceFrom）、执行主题（sourceTopic，即 MQTT 主题路径）、边缘网关 ID 和设备编码。

表格列包含：执行动作名称、设备所在地理位置（属地/楼层区域/楼层/区域的多级空间路径）、执行设备（格式化设备路径）、执行者来源和触发时间。

#### 日志导出

工具栏提供"导出"按钮，将当前筛选结果导出为 Excel 文件，调用专用导出接口（带有加载状态），便于离线分析和存档。

## 3.6.11 IP 摄像头与流媒体管理

### 功能入口

设备管理 → IP 摄像头

### 功能描述

IP 摄像头管理集成 ZLMediaKit 流媒体服务，提供摄像头的注册、拉流代理管理、实时预览和历史回放能力。

#### 摄像头列表

左侧空间树按位置组织摄像头。右侧以卡片网格展示摄像头，每张卡片包含摄像头名称（IP 地址）和内嵌 Jessibuca 播放器（基于 WASM 的 HTML5 播放器，支持 H.264/H.265 解码）。卡片提供编辑、拉流、播放/暂停和取消拉流操作按钮。

#### 摄像头配置

编辑抽屉提供丰富的流媒体参数配置（前 6 个字段默认显示，点击"展开更多"显示全部）：

**基础配置**——摄像头名称、IP 地址、应用名（如"live"）、流 ID 名、拉流地址（RTSP URL）、RTSP 拉流方式（TCP/UDP/组播）。

**拉流设置**——拉流重试次数（默认 3 次）、拉流超时时间（默认 15 秒）。

**协议转换**——六个独立开关控制 HLS、HLS-fmp4、MP4 录制、RTSP、RTMP、HTTP-TS 和 HTTP-fmp4 协议转换的启停。

**按需转码**——五个独立开关控制 HLS、RTSP、RTMP、TS、fmp4 是否仅在有人观看时才启动转码，节省服务器资源。

**音频设置**——开启音频、添加静音音频（解决某些摄像头无声时播放异常的问题）。

**MP4 录制**——保存路径（默认 `./www`）、最大录制时长（默认 3600 秒）。

**时间戳模式**——绝对时间戳/系统时间戳/相对时间戳三种模式可选。

**自动关闭**——无人观看时自动停止拉流，释放服务器和带宽资源。

#### 流媒体控制

- **拉流**——调用 ZLMediaKit 的 addStreamProxy API 添加 RTSP 流代理，返回播放 URL
- **播放/暂停**——通过 Jessibuca 播放器实例控制，支持 FLV、HLS、WebSocket 多种播放协议，支持截图、全屏、带宽显示和音频控制
- **取消拉流**——调用 delStreamProxy API 删除流代理，释放服务器资源

## 3.6.12 超出标书范围的能力

本系统在标书要求的十大功能之外，额外提供以下增强能力：

**Node-RED 可视化流程编排**——以边缘网关内置的 Node-RED 引擎替代传统组态软件，提供更灵活的零代码自动化流程编排能力。每条自动化流程以节点连线的方式可视化呈现，支持 MQTT、HTTP、Modbus、BACnet 等多种工业协议节点的即拖即用。流程部署后支持运行时数据流动画效果和版本回滚。

**16 类物联网设备全生命周期管理**——从网关接入、设备注册、实时状态监控（MQTT 准实时）、设备点位标注（AirocovMap 3D 地图）、场景自动化编排到操作日志审计，构成设备的完整生命周期管理闭环。

**设备巡检自动化**——支持按楼层范围的批量设备巡检，巡检过程自动化（逐层 MQTT 状态采集），巡检结果支持 PDF 导出。会议室巡检支持多设备联合异常检测（如照明+空调同时离线判定为断电）。

**IP 摄像头与流媒体一体化**——集成 ZLMediaKit 流媒体服务器和 Jessibuca HTML5 播放器，支持 RTSP 流代理管理、多协议转换（HLS/RTMP/HTTP-TS/fmp4）、按需转码、MP4 录制、音频处理和自动关闭等完整的流媒体管理能力。

**运营综合看板体系**——除环境监测看板外，系统还提供安防看板（告警趋势 24h + 类型分布 + 摄像头状态）、告警看板（周趋势 + 按来源/按区域分布）、通行看板（车流趋势 + 人员密度）、餐厅看板（就餐趋势 + 菜品统计）、会议看板（会议室使用率 + 部门频次统计）共六大运营看板，覆盖园区运营的核心数据维度。

**楼宇智控 15 类设备精细化管控**——每种设备类型均提供统一的操作框架（空间树 + 卡片网格 + 批量全开/全关 + 地图定位），设备卡片基于 MQTT 实时状态动态切换图标和颜色，支持对单个设备或全空间范围设备的即时远程控制。

**设备分组与聚合计算**——支持用户自定义设备分组（通过穿梭框选择设备），分组支持传感类型（配置聚合计算公式如平均值/求和）和控制类型，分组数据可对接 MQTT 主题，实现分组维度的设备状态统一监控。
