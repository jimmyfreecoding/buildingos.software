# 3.12 园区运营中心

## 需求概述

本系统提供覆盖园区空间、安防、资产、基础设施、能效、通行、智慧空间和智能工单等管理领域的综合运营态势监测分析平台。园区运营中心以多维度可视化看板为载体，将园区人、事、物的运行状态汇聚于统一界面，实现园区综合运营态势一屏掌握。系统以六个专题看板（安防看板、告警看板、通行看板、环境看板、餐厅看板、会议看板）覆盖八大管理领域，通过 ECharts 图表、统计卡片、数据表格和实时状态标识的组合呈现方式，为园区管理者提供从宏观指标到微观明细的完整运营视图。

---

## 3.11.1 整体架构

### 模块总览

园区运营中心包含六个专题看板，通过顶部标签页或左侧菜单切换：

**安防看板**——以 6 个摘要卡片、摄像头状态列表、24 小时告警趋势图、告警类型分布环形图和近期安防事件表，呈现园区安全管理全貌。

**告警看板**——以 6 个摘要卡片、7 天告警趋势图、告警来源分析、区域分布环形图和分页告警事件表，提供告警全生命周期管理视图。

**通行看板**——以 4 个摘要卡片、车流进出趋势图、区域人员密度图、车位使用环形图和车辆通行记录表，展示园区人流和车流态势。

**环境看板**——以 8 个仪表卡片、温度趋势多线图和环境传感器明细表，综合展示园区空间环境质量。

**餐厅看板**——以 6 个摘要卡片、就餐趋势图、分区就餐分布图、今日菜单表和周度用餐统计图，呈现园区餐饮运营态势。

**会议看板**——以 6 个摘要卡片、会议室实时状态网格、部门会议统计图、当前进行中会议列表和周度会议趋势图，展示会议室资源使用全貌。

### 技术架构

园区运营中心拥有独立的 NestJS 后端微服务（端口 3038），支持 Docker 独立部署或嵌入主进程（NPM_INSTALL 模式）两种运行模式。后端提供完整的 REST API 和 Swagger 文档（`/operations/docs`），通过 MQTT 协议实现微服务间通信。前端使用 Vue 3 + TypeScript + Element Plus 构建，以 ECharts 5（vue-echarts）为核心可视化引擎，各看板的数据通过独立 API 函数获取并渲染。当前系统以 Mock 数据驱动前端演示，后端 API 接口已预留，可无缝切换至真实数据源。

## 3.11.2 综合态势

### 功能描述

园区运营中心以六个专题看板的集合实现标书要求的"综合态势"能力。各看板覆盖园区空间、安防、资产、基础设施、能效等管理领域的关键指标，通过统一的操作界面进行综合监测分析，实现园区人、事、物的统一管理。

每个看板页面均以统一的视觉风格构建：页面顶部排列彩色摘要统计卡片，展示该领域的核心 KPI 数字；中部以 ECharts 图表组合呈现趋势、分布和对比分析；底部以数据表格展示明细记录。各看板数据通过独立的 API 函数（`getSecurityOverview`、`getAlarmOverview` 等）获取，支持后续对接真实数据源。

#### 全局数据刷新

所有看板的数据在页面加载时通过 `Promise.all` 并行请求多个 API 接口，统一获取后分发渲染。摘要卡片的数值通过 computed 属性从接口数据中实时计算（如响应率 = 已处理数 / 总告警数 × 100%），确保指标口径一致。

## 3.11.3 安全管理

### 功能入口

园区运营中心 → 安防看板 / 告警看板

### 功能描述

安全管理由安防看板和告警看板两个专题页面共同支撑，覆盖标书要求的重点部位监控、人员车辆实时监测、安防报警事件快速显示与定位、事件周边监控视频调取等能力。

### 安防看板

安防看板采用左右双栏布局（30% 左侧 + 70% 右侧），顶部全宽排列六个摘要统计卡片。

#### 六个摘要卡片

- **今日告警**（红色卡片）——当日系统产生的告警总数
- **待处理**（橙色卡片）——当前尚未闭环的告警数量
- **在线摄像头**（绿色卡片）——当前在线运行的摄像头数量
- **离线摄像头**（灰色卡片）——当前离线的摄像头数量
- **安保人员**（蓝色卡片）——当前在岗的安保人员总数
- **巡逻路线**（紫色卡片）——当日已规划的巡逻路线数量

每个卡片采用左侧彩色边框 + 图标容器 + 大号数值 + 标签的标准化布局，卡片悬停时产生阴影提升效果。

#### 摄像头状态列表

左侧区域以卡片包裹数据表格，展示园区各摄像头的实时状态。表格列包含：摄像头名称（如"A栋大厅-东""园区南门"）、所属区域、在线状态（以绿色/灰色标签区分在线/离线）、最后检测时间。6 条模拟数据覆盖各楼栋主要出入口和重点区域。

#### 告警趋势与分布

右侧区域以两个 ECharts 图表并列展示：

**24小时告警趋势**——双轴组合图表，蓝色柱状图展示每小时告警数量，绿色平滑折线叠加展示每小时已处理数量。X 轴为 24 小时（00:00-23:00），顶部图例区分"告警数"和"已处理"。图表直观反映告警的时段分布和处理效率。

**告警类型分布**——环形图（半径 40%-70%），展示六种告警类型的占比：入侵检测、火灾预警、门禁异常、视频离线、周界报警、设备故障。每种类型以独立颜色标识，扇区标签显示类型名称和百分比数值。

#### 近期安防事件

右侧底部表格展示近期安防事件明细，六列信息：时间、类型（以彩色标签标识）、区域、级别（以红色/橙色/灰色标签区分高/中/低）、描述、处理状态（已处理/处理中）。

### 告警看板

告警看板以全宽单列布局，提供完整的告警全生命周期管理视图，支持多维度筛选过滤和分页查询。

#### 多维度筛选

顶部查询栏（vab-query-form）提供五维筛选条件：
- 日期范围选择器（YYYY-MM-DD 格式）
- 告警级别筛选（全部/高/中/低）
- 处理状态筛选（全部/已处理/处理中/未处理）
- 所属区域筛选（全部/A栋/B栋/C栋/园区户外/地下车库）
- 告警类型筛选（全部/入侵检测/火灾预警/门禁异常/设备故障/周界报警）

右侧提供查询和重置按钮，筛选参数即时生效，触发列表和统计卡片同步更新。

#### 六个摘要卡片

卡片数据随筛选条件动态重新计算：
- **总告警**（蓝色卡片）——筛选范围内的告警总数
- **已处理**（绿色卡片）——已完成闭环的告警数量
- **处理中**（橙色卡片）——正在处理中的告警数量
- **未处理**（红色卡片）——尚未开始处理的告警数量
- **响应率**（紫色卡片）——已响应告警占总告警的百分比（如 94.3%）
- **平均响应**（青色卡片）——从告警触发到开始处理的平均耗时（如 3.2 分钟）

#### 三维分析图表

卡片下方以三列等宽布局展示三个分析图表：

**7天告警趋势**——柱状图 + 折线图组合，蓝色圆角柱状图展示最近 7 天每日告警总数，绿色折线展示每日已处理数量。通过趋势曲线可识别告警高发日和周末低谷期。

**告警来源分析**——横向柱状图，按来源系统展示告警数量排名：视频分析（42）、传感器（38）、门禁系统（30）、手动上报（25）、巡检发现（15）、系统自检（8）。每个来源以独立颜色区分，数值标签显示在柱状条右侧。

**区域分布**——环形图（半径 40%-70%），展示五个区域的告警数量比例：A栋（45）、B栋（38）、C栋（32）、园区户外（28）、地下车库（15）。通过扇区面积直观对比各区域的安全风险集中度。

#### 告警事件列表

底部全宽分页表格展示过滤后的告警事件明细，八列信息：时间、类型（彩色标签）、区域、来源、级别（分别以红色/橙色/灰色标签标识高/中/低）、状态（已处理/处理中/未处理，以不同颜色标签区分）、处理人、描述。表格支持斑马纹样式、加载状态（v-loading）和空数据提示。分页组件支持每页 10/20/50/100 条切换、页码跳转和总数显示。

## 3.11.4 能耗管理

### 功能描述

标书要求的能耗管理（供暖、供排水、供气、供电等系统运行态势监控和能耗数据分析）由两个层面协同实现：

**设备设施监控模块**（详见第 3.6 章设备设施监控）——提供各能源子系统（供电/供水/燃气/供暖/空调）的设备运行监测、实时参数采集和能耗趋势分析。系统通过 MQTT 协议从边缘网关获取传感数据，以 TDengine 时序数据库存储历史数据，支持按日/周/月的时间粒度统计能耗用量。

**环境看板**（详见第 3.11.6 节智慧空间中的环境看板）——提供温度、湿度、AQI、PM2.5、CO2、TVOC、噪音七项环境参数的实时监测，间接反映园区的能源使用效益。环境数据与空调系统、新风系统的能耗之间存在联动分析关系。

两个模块的共同覆盖实现标书要求的能耗管理能力。详细的能耗监测功能描述请参阅设备设施监控章节。

---

## 3.11.5 设备管理

### 功能描述

标书要求的设备设施类型、分布、状态和详细信息监测覆盖于多个模块之中：

**设备设施监控模块**（详见第 3.6 章）——提供设备类型分类（16 个设备类型标签页）、设备空间分布（AirocovMap 三维地图定位）、设备在线率监测（MQTT 实时心跳）和设备运行分析等核心能力。

**环境看板**（详见第 3.11.6 节）——以传感器明细表展示各区域环境监测设备的状态，包括设备所属区域、各参数读数、设备健康状态（正常/告警/异常）等详细信息。

**信息发布模块**（详见第 3.11 章）——提供信息发布设备的按区域和设备类型分组管理、在线状态监控和远程操作能力。

各模块通过统一的设备编码体系关联，在运营中心层面实现跨设备类型的统一监测视图。

## 3.11.6 通行管理

### 功能入口

园区运营中心 → 通行看板

### 功能描述

通行看板以全宽单列布局，覆盖标书要求的车辆通行情况、车位使用情况和人员密度三大通行管理要素。

#### 四个摘要卡片

页面顶部以四列等宽布局展示核心通行指标，每个卡片采用 el-card 加悬停阴影样式：

**今日车流量**（蓝色卡片）——当日进出园区的车辆总数（如 1856 辆），附带环比变化趋势箭头（如 ↑12.5%），辅助管理者快速判断车流变化方向。

**车位占用率**（绿色卡片）——当前园区总车位占用百分比（如 78%），以圆形进度环可视化展示占用比例，副标题显示"可用车位数"（如 110 个）。

**在园人数**（紫色卡片）——当前园区内的人员总数（如 2,340 人），附带人员密度百分比（如 65%），辅助判断园区人员承载状态。

**今日访客**（橙色卡片）——当日登记的访客总数（如 89 人），帮助管理者了解外部人员进入规模。

#### 车流进出趋势

左侧区域（宽度 50%）展示车流进出趋势图。ECharts 分组柱状图以绿色柱表示入场车流量，红色柱表示出场车流量，X 轴覆盖 14 个时段（06:00-19:00）。图表直观反映通勤规律——早高峰（08:00）入场车辆最多（约 180 辆），晚高峰（17:00）出场车辆最多（约 160 辆）。自定义图例以颜色圆点区分进出方向，tooltip 悬浮显示各时段的入/出场精确数值。

#### 区域人员密度

右侧区域（宽度 50%）展示各区域的人员密度横向柱状图。柱状条使用线性渐变色（绿→黄→红），密度从低到高颜色逐步从绿色过渡为黄色再至红色，实现密度热力图的视觉映射。八个监测区域的密度数据覆盖各楼栋楼层和公共区域：A栋1F（85%）、A栋3F（60%）、B栋1F（72%）、B栋2F（58%）、C栋1F（78%）、C栋5F（45%）、餐厅（92%）、地下车库（35%）。数值标签以百分比形式显示在柱状条右侧。

#### 车位使用详情

左侧区域（宽度约 42%）以环形图展示园区总体车位占用率——红色扇区为"已占用"部分，灰色扇区为"空闲"部分。环形中心以文字显示"已用 X / 总 Y 车位"的总览信息，附绿色标签"可用 Z"。

环形图下方按四个分区展示车位的详细占用情况：A栋B1、B栋B1、C栋B1、地面停车场。每个分区以 el-progress 横向进度条 + 文字标签（已用数/总数）展示，数值按比例从总车位数据中拆分计算。

#### 车辆通行记录

右侧区域（宽度约 58%）以表格展示近期车辆通行记录明细：车牌号（如京A-12345）、车辆类型（临时车/月租车/访客车/VIP，以不同颜色标签区分）、入场时间、出场时间、所属区域、在场状态（绿色"在场"/灰色"已出场"）。表格支持空数据提示。

## 3.11.7 智慧空间

### 功能描述

智慧空间能力通过环境看板、餐厅看板和会议看板三个专题页面协同实现，覆盖标书要求的空间资源使用和环境数据综合可视分析。

### 环境看板

#### 功能入口

园区运营中心 → 环境看板

#### 功能描述

环境看板以全宽布局，通过仪表卡片、趋势图和传感器明细表构建园区环境质量的综合监测视图。

#### 八个仪表卡片

页面顶部以八列等宽布局展示环境核心参数，每个卡片采用顶部彩色边框（3px 实线）+ 大号数值 + 标签的布局：

- **温度**（蓝色边框）——当前园区平均温度（如 24.5°C）
- **湿度**（绿色边框）——当前园区平均相对湿度（如 55%）
- **AQI**（绿色边框）——当前空气质量指数（如 68），附空气质量等级文字（如"良"）
- **PM2.5**（橙色边框）——当前 PM2.5 浓度（如 35 μg/m³）
- **CO2**（紫色边框）——当前二氧化碳浓度（如 580 ppm）
- **TVOC**（粉色边框）——当前总挥发性有机物浓度（如 0.08 mg/m³）
- **噪音**（黄色边框）——当前环境噪声分贝值（如 52 dB）
- **舒适度**（蓝色边框）——综合评价得分（0-100）

#### 舒适度算法

舒适度指数通过客户端综合算法计算，融合七项环境参数按权重评分：温度（理想值 22°C）、湿度（理想值 50%）、AQI、PM2.5、CO2（基准 400 ppm）、TVOC、噪音（理想值 45 dB）。得分 ≥85 为"舒适"，≥70 为"良好"，≥55 为"一般"，<55 为"较差"。此评分算法纯前端计算，可灵活调整权重以适应不同园区的环境标准。

#### 温度趋势图

全宽 ECharts 多线图展示各楼栋的温度变化趋势。三条彩色曲线分别代表 A栋（蓝色）、B栋（绿色）、C栋（橙色），X 轴覆盖 15 个小时（06:00-20:00），Y 轴为摄氏温度。每条曲线下方以半透明渐变填充区域，曲线为平滑样式。自定义 HTML tooltip 以彩色圆点 + 系列名称 + 温度值的形式展示各时间点的精确读数。

#### 环境传感器明细表

全宽分页表格展示各区域环境传感器的详细读数，六列信息：所属区域、温度（超过 26°C 时数值以红色高亮显示）、湿度、PM2.5（以进度条可视化展示相对 75 μg/m³ 阈值的比例）、CO2（以进度条可视化展示相对 2000 ppm 阈值的比例）、噪音、设备状态（正常绿色/告警橙色/异常红色）。8 条模拟数据覆盖各楼栋主要楼层和公共区域的传感器点位。表格支持加载状态和空数据提示。

### 餐厅看板

#### 功能入口

园区运营中心 → 餐厅看板

#### 功能描述

餐厅看板以全宽布局展示园区餐饮空间的运营态势，覆盖就餐人数、座位利用率、排队时间和用餐统计。

#### 六个摘要卡片

- **当前就餐人数**（蓝色卡片）——实时就餐人数（如 420 人）
- **座位占用率**（绿色卡片）——当前座位使用率（如 72%），以自定义 SVG 圆形进度环可视化展示占用比例
- **今日用餐总数**（紫色卡片）——当日累计用餐总人次（如 1,680 人次）
- **平均排队时间**（橙色卡片）——当前平均排队等候时长（如 8 分钟）
- **高峰时段**（红色卡片）——用餐高峰时间段（如 11:30-12:30），以副标题形式显示
- **总座位数**（青色卡片）——餐厅总座位容量（如 580 个）

#### 就餐趋势与分区分布

左侧区域（宽度 35%）展示**就餐趋势图**。ECharts 柱状图 + 折线图组合——柱状条采用渐变色：非高峰时段为蓝色，高峰时段（11:30-12:30）为红橙渐变，叠加绿色平滑趋势折线。X 轴覆盖 16 个时段（07:00-19:00），峰值出现在 12:00（420 人就餐）。自定义 tooltip 同时显示柱状图数值（人数）和折线图数值（趋势）。

中部区域（宽度 35%）展示**分区就餐分布图**。ECharts 双柱叠加横向图（barGap: '-100%'），蓝色柱体表示各区域的用餐人数（中餐区 220、西餐区 80、面点区 60、饮品区 35、户外区 25），半透明蓝色覆盖柱体表示各区域的座位占用率百分比。tooltip 展示区域名称、用餐人数、座位总数和占用率。

#### 今日菜单

右侧区域（宽度 30%）展示今日菜单数据表格，五列信息：菜品名称、品类（以彩色标签区分中餐/西餐/面点/饮品/户外）、价格（以红色字体和人民币符号显示）、销量（支持排序，默认按销量降序排列）、评分（以 el-rate 星级评分组件展示，只读模式）。6 条模拟菜品数据（如红烧肉、清蒸鲈鱼、意大利面）。

#### 周度用餐统计

底部全宽展示 ECharts 分组柱状图，按周七天（周一至周日）展示早餐、午餐、晚餐三组柱状条。工作日用餐人数较高（约 1,200 人/天），周末降至约 400 人/天，符合办公园区餐饮消费规律。

### 会议看板

#### 功能入口

园区运营中心 → 会议看板

#### 功能描述

会议看板以双栏 + 全宽底部的布局展示会议室资源的实时状态和使用分析。

#### 六个摘要卡片

- **今日会议数**（蓝色卡片）——当日预定的会议总数（如 48 个）
- **进行中**（绿色卡片）——当前正在进行的会议数量（如 8 个），附带 CSS 动画脉冲绿色圆点，直观提示当前活跃会议状态
- **会议室使用率**（紫色卡片）——当前会议室的时间占用率（如 72.5%），附带"%"单位
- **参会总人数**（橙色卡片）——当日所有会议的参会人员总数（如 320 人）
- **待开会议**（青色卡片）——后续时段待开始的会议数量（如 15 个）
- **平均时长**（灰色卡片）——当日会议的平均持续时长（如 65 分钟），附带"分钟"单位

#### 会议室实时状态网格

左侧区域（宽度 40%）以 2×2 CSS 网格展示会议室卡片。每个会议室卡片包含：房间名称、容纳人数标签、彩色状态指示圆点（蓝色进行中、绿色空闲、橙色已预定、灰色维护中）、进行中会议时显示会议主题和预计结束时间。10 间会议室分布于 A栋、B栋和 C栋。

#### 部门会议统计

右侧上部展示 ECharts 双柱横向图，蓝色柱体为各部门会议次数，橙色柱体为各部门累计使用时长。六个部门（技术部、市场部、产品部、行政部、财务部、人事部）按次数降序排列，直观对比各部门对会议室资源的使用强度差异。

#### 当前进行中会议列表

右侧下部表格展示当前正在进行的会议：会议室、会议主题（溢出省略 + tooltip 显示全文）、所属部门、主持人、时间段（蓝色标签）、参会人数。限制显示 5 条最近记录。

#### 周度会议趋势

底部全宽 ECharts 双 Y 轴图表。蓝色柱状图（左 Y 轴）展示每日会议次数，绿色折线（右 Y 轴，范围 0-100）展示每日会议室使用率。X 轴为周七天。工作日每天约 42-55 场会议、使用率 65%-82%，周末降至每天 5-8 场、使用率 10%-15%，符合办公园区会议规律。

## 3.11.8 智能工单

### 功能描述

标书要求的工单满意度、完成率、按时完成率、响应率、新增工单、高频工单、差评工单和人员排名等分析功能，由工单管理模块的统计分析看板覆盖（详见第 3.7 章工单管理）。

工单统计分析看板提供以下完整能力：

**五个摘要卡片**——总工单数、已完成工单数、处理中工单数、总响应率百分比、平均处理时长，从全局维度汇总工单运营的核心 KPI。

**ECharts 分析图表**——工单趋势折线图（按日期展示新增和完成的数量变化），工单来源分布统计表，工单类型分布统计表，为高频工单分析和资源配置优化提供数据支撑。

**工单服务评价体系**——工单闭环时记录服务评价（满意度评分、差评原因），差评工单可通过列表筛选快速定位，用于服务质量改进。

**人员绩效排名**——基于处理工单数量、完成率、按时完成率、平均响应时间等维度综合评估处理人员的绩效表现，支持排行榜展示。

运营中心层面通过统一导航入口快速跳转至工单管理模块，实现从综合态势到专业工单分析的无缝切换。

## 3.11.9 全局设置

### 功能描述

标书要求的全局设置能力（自定义配置模块、背景图片、标题、展示卡片、自定义上传数据和个性化展示卡片）当前处于规划阶段，系统架构已预留扩展空间：

**模块配置扩展点**——各看板的 API 接口采用统一的数据返回格式（`{ code, msg, data }`），后续可通过配置 API 动态控制各看板的卡片显示/隐藏、布局顺序和主题颜色，无需修改前端代码。

**数据源切换能力**——当前系统以 Mock 数据驱动前端演示，所有 API 函数均遵循统一的 `Promise` 返回格式。后端 NestJS 微服务已预留完整的 REST API 端点，对接真实数据源时仅需替换 API 层的 Mock 实现，前端可视化层保持不变。

**个性化卡片扩展**——摘要卡片的 UI 组件结构已标准化（彩色左边框 + 图标 + 数值 + 标签），新增自定义展示卡片仅需配置图标、颜色、数据字段和标签文案五个参数即可快速集成到任意看板页面。

## 3.11.10 超出标书范围的能力

本系统在标书要求的八大功能之外，额外提供以下增强能力：

**六大专题看板覆盖运营全景**——除标书要求的管理领域外，额外提供餐厅看板（就餐人数、座位占用、排队时间、菜品评分、周度统计）和会议看板（会议室实时状态、部门使用统计、周度趋势），将园区运营的监测范围从安防、设备、空间扩展到餐饮服务和会议资源，实现更全面的运营态势感知。

**舒适度智能评分算法**——环境看板内置七因子加权评分算法，将温度、湿度、AQI、PM2.5、CO2、TVOC 和噪音七项环境参数融合为一个 0-100 的综合舒适度得分，分四级（舒适/良好/一般/较差）呈现，为园区环境品质管理提供直观的量化指标。

**多维度组合筛选**——告警看板提供日期范围 × 告警级别 × 处理状态 × 所属区域 × 告警类型的五维组合筛选，筛选参数联动更新所有统计卡片和图表，实现从宏观到微观的数据下钻分析。

**动效状态提示**——会议看板中的"进行中"卡片使用 CSS 关键帧动画脉冲绿色圆点，直观提示当前活跃会议状态，增强实时监测的视觉感知。

**ECharts 双 Y 轴组合图表**——会议看板的周度趋势图使用双 Y 轴设计，左轴对应会议次数（柱状图），右轴对应使用率百分比（折线图），在一个图表内同时展示绝对数量和相对比率两个不同量纲的指标，避免双图表占用的空间浪费。

**独立后端微服务架构**——运营中心拥有独立的 NestJS 微服务（端口 3038），支持 Docker 独立部署和嵌入主进程两种运行模式，通过 MQTT 协议实现微服务间通信和健康检查，JWT 认证与主系统一致。Swagger 文档（`/operations/docs`）为后续对接真实数据源提供完整的 API 参考。
