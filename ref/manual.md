# 操作说明书编写规范

## 一、版权局格式要求

### 截图规范
1. 软件截图中的软件名字必须与申请表中的软件全称或简称一致。
2. 单幅软件截图必须完整，边缘不能裁剪图中文字。
3. 截图图片中不能出现马赛克、商标、日期、具体时间、网址、姓名、和与软件无关的名称。
4. 最少不低于6页（不包含封面和目录），最多不超过60页。

### 内容要求
1. 操作手册须含有完整、详细的操作步骤截图，及相关的文字说明，能提供越多越好。
2. 如果软件没有操作界面，提供设计说明书。设计说明须含详细的软件结构图、各个功能的流程图、逻辑框图，介绍软件总体设计、接口设计、模块名称功能、函数名称功能、算法、运行设计等内容。

## 三、编写要点

### 3.1 命名一致性
- 文档标题、引言中的系统名称、截图中的软件名称必须与申请表完全一致。
- 格式：`{系统全称} {系统简称}`，如「智能楼宇通行系统 Buildingos.access」。

### 3.2 截图标注
- 所有截图使用 `![描述](image-N.png)` 格式，N 从 0 开始递增。
- 每张截图下方紧跟一行 `*图 X-Y 界面描述*`，X为章节号，Y为图序号。
- 图片文件放在与 manual.md 同目录下。

### 3.3 内容密度
- 每个 3.x 模块节至少包含「功能说明」和「界面展示」两部分。
- 核心功能建议增加「操作步骤」子节。
- 功能模块数量建议 4-6 个（对应 3.2 - 3.7），总计至少 10 个子节。

### 3.4 软件运行环境
- 硬件环境和软件环境必须与 copyright.md 中填写的一致。
- 服务端配置写推荐值，不需要精确到具体品牌型号。

### 3.5 参考范例
完整范例参见 `docs/access/manual.md` 或 `docs/visitor/manual.md`（已成功申请的5个系统）。
