# 3.8 设备智控

## 需求概述

本系统提供基于可视化策略编辑器的楼宇设备智能控制解决方案。以"物理位置 × 时间类型 × 策略条件"的三维组合模型为核心，支持按工作日、休息日、节假日分别配置定时开关、温控触发、AI 人密检测和人体感应等多种控制策略。策略经序列化后由 Node-RED 消费并以 Cron 定时任务自动执行，同时提供策略执行日志、冲突检测、AI 辅助创建、一键生效和日历管理等功能。

---

## 3.8.1 整体架构

### 核心思路

设备智控模块的核心设计思想是**"物理位置 × 时间类型 × 策略条件"的任意组合**。运营人员通过可视化界面定义策略，将物理设备地址、日期类型（工作日/非工作日/假期/特定日期）和策略条件（定时/温控/AI/人体感应）进行自由组合，最终生成一个完整的 JSON 策略文件。

策略保存时，前端将嵌套结构展平为按日期类型分组的平铺规则数组，写入后端数据库。Node-RED 从数据库读取策略，按 Cron 表达式定时执行每条规则，通过 MQTT 向边缘网关下发设备控制指令。

### 数据模型

策略数据采用四层嵌套结构：

**第一层（策略）**——定义一个完整的设备控制策略，包含策略名称、策略类型（照明/温控/告警）、生效日期范围和关联的区域列表。

**第二层（区域组）**——将物理区域按逻辑分组，如"楼层办公区""会议室""公共区域"。

**第三层（细分区域）**——绑定具体的物理地址（楼栋/楼层/区域编码）、适用的日期类型（workday/weekend/holiday/特定日期）和策略条件类型（time/temperature/ai/human），以及具体的控制规则列表。

**第四层（规则）**——单条设备控制指令，包含开始时间、结束时间、描述和具体的设备指令 payload（如开/关、温度设定值、运行模式等）。

### 模块总览

设备智控模块包含以下功能入口：

**策略编辑器（主界面）**——左侧策略树 + 右侧时间轴可视化表格，支持策略的创建、编辑、删除和保存。

**日历管理**——基于 FullCalendar 6 的工作日/假期日历，定义全年日期分类。

**工作日规则**——配置工作日判定规则，决定哪些日期匹配"workday"类型。

**策略执行日志**——记录每条策略的实际执行历史和操作明细。

**快速创建向导**——填表式快速创建完整策略，降低策略配置门槛。

**AI 辅助创建**——通过 AI 面板输入自然语言描述，自动生成策略 JSON 并预览冲突。

**冲突检测**——自动检测同一天内同一设备是否存在时间重叠的冲突规则。

**JSON 编辑器**——提供原始 JSON 的查看和导出，便于备份和跨环境迁移。

## 3.8.2 策略编辑器

### 功能入口

楼宇智控 → 策略配置

### 功能描述

策略编辑器是整个设备智控模块的核心操作界面，采用左侧策略树 + 右侧时间轴可视化表格的双栏布局。

#### 左侧策略树

左侧以树形结构展示当前空间下的所有策略，树节点按"策略名称 → 区域组 → 细分区域"三层组织。点击某个策略节点后右侧时间轴加载该策略的完整规则布局。树的构建基于从后端加载的完整策略 JSON 数据。

#### 右侧时间轴可视化

时间轴表格是策略编辑器的核心可视化组件，将策略数据渲染为二维时间矩阵：

**Y 轴（行）**——时间槽，从 00:00 到 23:59，每 30 分钟为一行，早高峰时段（09:00-10:00）细化到每 10 分钟一行，确保关键时段的精确控制。

**X 轴（列）**——细分区域 × 日期类型 × 策略条件的三维笛卡尔积展开。每个"细分区域 + 日期类型 + 策略条件"组合占据一列。

**表头（5 行固定）**——采用 sticky 定位始终可见：
- 第 1 行：策略名称栏 + 区域名称下拉快速跳转菜单
- 第 2 行：区域类型（逻辑区域组名，如"楼层办公区""会议室"）
- 第 3 行：区域明细名称 + 查看物理地址按钮
- 第 4 行：日期类型标签（工作日/非工作日/假期/特定日期）
- 第 5 行：策略条件类型标签（定时/温控/AI/人体感应）

**单元格合并**——带有结束时间的规则在时间轴上跨多行合并（rowspan），形成一个跨时间段的彩色矩形块，直观展示规则的持续时长。

**颜色编码**——不同策略条件类型以不同颜色标识：
- 红色——定时任务（time）
- 橙色——温控触发（temperature）
- 蓝色——AI 摄像头/人体感应（ai/human）
- 深红色——告警规则（alarm）

**点击交互**——点击任意有色单元格，弹出 TimeActionEdit 抽屉，可直接编辑该规则的参数（时间范围、设备指令 payload），或删除该规则。修改后策略标记为脏状态，顶部出现"保存"按钮。

#### 策略创建与编辑

**策略抽屉（SenceEdit）**——配置策略的基本信息：策略名称、策略类型（照明/温控/告警）、生效日期范围（开始日期至结束日期）、区域列表管理。

**细分区域配置（SenceActionEdit）**——为策略添加细分区域，配置：
- 适用日期类型（多选：工作日/非工作日/假期/特定日期）
- 策略条件类型（多选：定时/温控/AI/人体感应/温度告警/空气告警）
- 物理地址绑定：通过级联选择器选择"楼栋 → 楼层 → 区域"，系统自动遍历空间树匹配物理地址编码，生成 realadress 数组
- 支持生效楼层和排除楼层的配置，通过"有效楼层 − 排除楼层"计算实际生效的楼层范围

**规则编辑（TimeActionEdit）**——编辑单条设备控制规则，根据策略类型和策略条件类型渲染不同的表单：
- 定时（light）：开关指令（开/关）
- 定时（air）：开关指令 + 设定温度（16-29°C）+ 运行模式（制冷/制热/送风/自动）+ 风速（低/中/高）
- 温控触发：温度条件判断（>/</范围内）+ 触发温度阈值 + 设定温度 + 运行模式 + 风速
- AI/人体感应：无人持续分钟数（超过后自动关闭）
- 温度告警：温度条件（>/</>=/<=/不等于）+ 告警温度阈值
- 空气质量告警：指标类型（CO2/PM2.5/TVOC）+ 条件判断 + 阈值 + 单位 + 执行标准说明

#### 保存与生效

**保存**——点击保存按钮后，系统执行以下流程：
1. `transformSceneData()` 将四层嵌套结构展平为按 dayType 分组的平铺规则数组
2. 楼层间隔时间处理（控制同楼层设备指令的发送间隔，避免并发过大）
3. 清理策略 JSON 中的冗余数据
4. 通过 API `POST /sence/saveSenceJson` 写入数据库
5. 保存成功后重新加载策略数据

**立即生效**——保存后的策略默认等待 Node-RED 的定时 Cron 任务加载（通常有 1-2 分钟延迟）。点击"立即生效"按钮后，系统通过 MQTT 向主题 `/iot/action/policy/valid` 发送消息，Node-RED 收到后立即从数据库重新拉取策略 JSON，重置所有 Cron 任务，实现策略的即时热加载。

**导出**——支持将策略 JSON 导出为 `.json` 文件下载，便于备份和跨环境迁移。

**JSON 编辑器**——通过 json-editor-vue 组件直接查看和编辑策略原始 JSON，支持高级用户的批量修改。

## 3.8.3 定时控制（工作日/休息日差异化）

### 功能描述

定时控制是设备智控最核心的功能，支持对同一批设备按工作日、休息日、节假日分别设置完全不同的定时开关规则。

#### 日期类型体系

系统定义五种日期类型，通过日历管理维护：

**工作日（workday）**——周一至周五，支持通过日历配置调休（将周末调整为工作日）。系统根据 `choiceDay()` 函数判定当日日期类型，优先级为：精确日期 > 假期列表 > weekend > workday。

**非工作日（weekend）**——周六、周日，可通过日历将特定周末调整为工作日。

**假期（holiday）**——法定节假日，在日历管理中预设全年假期列表（如元旦、春节、清明节、劳动节、端午节、中秋节、国庆节）。每年需更新假期数据。

**特定日期（YYYY-MM-DD）**——精确日期匹配，优先级最高。适用于特殊活动日、设备检修日等一次性场景。

**假期集合（如"2025 假期"）**——假期通配符，匹配日历中标记的所有假期日期。

#### 工作日照明策略（示例）

工作日的照明控制按"上班开灯 → 午休关灯 → 午休后开灯 → 下班关灯"四段式编排：

- 08:00-12:00：上班时段开灯
- 12:00-13:00：午休关灯（节能）
- 13:00-19:00：下午工作时段开灯
- 19:00-24:00：下班关灯

#### 非工作日照明策略（示例）

非工作日（周末和假期）采用简化控制，不留午休关灯段：

- 00:00-09:00：早晨保持关灯
- 09:00-17:00：非工作日开放时段开灯
- 17:00-24:00：关闭

#### 四季温控策略（示例）

空调控制按季节分为春、夏、秋、冬四套策略，每套策略包含定时开关机（time）和温控条件触发（temperature）两种规则：

- **春季（3-5 月）**：自动模式 24°C，中风速
- **夏季（6-9 月）**：制冷模式 26°C，高风速，07:30-08:00 预冷 30 分钟
- **秋季（10-11 月）**：自动模式 24°C，中风速
- **冬季（1-2 月 + 12 月）**：制热模式 22°C，低风速，07:30-08:00 预热 30 分钟

每套策略的生效日期范围与季节对应，到期后自动失效，无需人工切换。

#### AI 人密检测策略（示例）

通过 AI 摄像头检测区域人员占用状态，无人超过设定分钟数后自动关灯，覆盖工作日的不同时段和非工作日：

- 工作时间（08:00-19:00，工作日）：无人 30 分钟后自动关灯（较宽容，避免频繁误关）
- 加班时段（19:00-22:00，工作日）：无人 15 分钟后自动关灯（较敏感，人走灯灭）
- 非工作日（09:00-17:00）：无人 20 分钟后自动关灯（中等灵敏度）

AI 规则独立于定时开关运行，两者不冲突——即使 AI 在工作时间关了灯，下一个定时规则（如午休后 13:00 开灯）会重新打开。

## 3.8.4 日历与工作日管理

### 功能入口

策略配置 → 日历管理

### 功能描述

日历管理模块使用 FullCalendar 6 组件，用于定义全年每一天的日期类型归属，是定时控制区分工作日/非工作日/假期的基础数据支撑。

#### 日历界面

FullCalendar 日历以月视图展示全年日期。通过点击日期可选择将其标记为工作日、非工作日或假期。假期可成批选择（如将春节 7 天统一标记为假期），不同日期类型以不同背景色区分显示。

日历数据通过独立 API 存储（`POST /sence/getSenceDayJson` / `POST /sence/saveSenceDayJson`），与策略 JSON 分离管理。

#### 工作日规则

工作日规则配置页（workday.vue）定义工作日的通用判定逻辑，如"周一至周五为工作日"的基本规则。系统结合日历标记和工作日规则，由 `choiceDay()` 函数计算任意给定日期的最终日期类型。

#### 假期预设

系统支持预设全年法定假期列表（如元旦、春节、清明节、劳动节、端午节、中秋节、国庆节），每年需手动更新假期日期。前端 `src/utils/sence.ts` 中的 `HOLIDAY_2025` 常量维护当前年度的假期数据。

## 3.8.5 策略执行日志与报表

### 功能入口

策略配置 → 执行日志

### 功能描述

策略执行日志记录每条设备控制策略的实际运行历史，提供操作记录查询和基线对比能力。

#### 日志查询

日志页面以表格展示策略执行记录，支持按执行场景（策略名称）和执行主题（MQTT 主题路径）筛选，支持按日期范围过滤。

查询栏提供关键字搜索、场景名称下拉筛选和时间周期（日期范围选择器）过滤器。

#### 日志记录内容

每条策略执行日志包含以下信息：

**执行场景名称**——记录触发该动作的策略名称（如"全年工作日照明""夏季空调"）。

**执行描述**——策略的简要描述信息，包括生效的区域范围和策略条件类型。

**执行内容（actionData）**——实际下发的设备指令 payload 完整内容，包括具体指令（开/关/温度值/模式等）、目标设备地址和触发条件。

**执行主题（actionTopic）**——MQTT 消息下发的主题路径，可用于追踪指令的传输路由。

**执行时间**——策略实际触发的精确时间戳（格式化为 YYYY-MM-DD HH:mm:ss）。

#### 数据导出

日志列表支持导出功能，将筛选后的日志数据导出为 Excel 文件。导出调用 `/sense/exportIotLog` 接口，触发时按钮显示加载状态，导出完成自动下载。

#### 基线对比

导出报表中包含每条策略规则的原始配置（基线数据）与实际执行内容的对比，便于审计设备控制是否符合预期策略。例如：某照明策略配置为 08:00 开灯，但实际执行日志显示 08:02 才下发指令（MQTT 网络延迟），此差异可在导出报表中进行对照分析。

#### 冲突检测

系统提供策略冲突检测功能。`findConflicts()` 函数遍历所有当前有效策略的展平规则，检测同一日期类型 + 同一空间编码 + 同一楼层区域 + 同一策略类型 + 同一策略条件类型下，存在时间区间重叠的规则。检测结果在抽屉中展示，高亮显示冲突的规则对和时间范围，帮助运营人员发现并修正策略配置错误。

## 3.8.6 快速创建与 AI 辅助

### 快速创建向导

快速创建向导（QuickSenceEdit）提供填表式策略创建界面，降低策略配置的学习门槛。用户通过向导依次填写：

1. 选择策略类型（照明/温控/告警）和命名策略
2. 选择楼栋、生效楼层范围和排除楼层
3. 勾选适用的区域类型（办公区/独立房间/公共区域/会议室/卫生间）
4. 选择适用日期类型（工作日/非工作日/假期）
5. 填写定时开关时间、温控参数或告警阈值
6. 向导自动生成完整的四层嵌套策略 JSON（含 areaDetail、realadress 和 action），无需手动逐层配置

### AI 辅助创建

通过 AI 面板（集成在策略编辑器页面），用户可用自然语言描述设备控制需求，AI 自动生成策略 JSON。

**交互流程**：
1. 点击"AI 配置"按钮，打开 AI 面板
2. 输入自然语言描述，如"帮我在 A 栋 3 楼设置一个工作日上班开灯、午休关灯、下班关灯的照明策略"
3. AI 返回策略 JSON 数据
4. 系统自动校验 JSON 格式完整性（`validateAiOutput()`）
5. 自动注入 UUID（`injectUUIDs()`）
6. 与已有策略进行时间冲突检测（`detectAiConflicts()`）
7. 预览模式：新策略显示在左侧策略树中，若有冲突则附带警告标记
8. 用户确认后点击"确认添加"，策略进入待保存状态

## 3.8.7 超出标书范围的能力

本系统在标书要求的两大功能之外，额外提供以下增强能力：

**六种策略条件类型**——除定时控制外，还支持温控条件触发（温度高于/低于/范围内阈值自动调节）、AI 摄像头人密检测（无人超时自动关灯/关空调）、人体红外感应、温度告警和空气质量告警（CO2/PM2.5/TVOC），构成设备控制的完整条件矩阵。

**四季温控自动切换**——按季节设置不同的空调温控策略（春/夏/秋/冬），每季独立配置温度设定值、运行模式和生效日期范围，到期自动切换，无需人工干预。

**可视化时间轴编辑器**——以二维时间矩阵直观展示策略规则的覆盖时间和重叠情况。不同策略条件类型以不同颜色区分，时间区间以跨行合并的彩色矩形呈现，点击单元格即可编辑参数。

**冲突检测机制**——自动扫描所有策略在任意时间点的规则重叠情况，检测结果以抽屉列表展示，防止多策略冲突导致设备控制混乱。

**AI 自然语言创建策略**——通过 AI 面板输入自然语言描述，AI 自动生成符合策略 JSON Schema 的完整配置，支持格式校验、UUID 注入和冲突预检测。

**Node-RED Cron 热加载**——策略保存后通过 MQTT 即时通知 Node-RED 重载策略，无需手动重启流程或等待下次 Cron 周期，实现策略配置的即时生效。

**策略 JSON 备份与跨环境迁移**——支持导出策略为 JSON 文件下载，以及通过 JSON 编辑器直接查看和批量编辑原始策略数据，便于备份、审计和跨环境（测试/生产）迁移。

**工作日日历管理**——基于 FullCalendar 6 的全年日期分类管理，支持工作日、非工作日和假期的灵活标记，支持调休（周末改为工作日）和假期列表预设，为定时控制提供精确的日期类型判定基础。
